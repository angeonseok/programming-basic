# 🐍 파이썬 예외 처리 · 파일 입출력

> 실행 중에 생기는 오류(**예외**)를 읽고 처리하는 법, 그리고 예외 처리와 짝을 이루는 **파일 입출력과 `with` 문**을 다룬다.

---

## 에러와 예외

### 에러 메시지 읽기 (Traceback)

> 에러 메시지는 **아래에서 위로** 읽는다. 맨 아래 줄이 에러의 종류와 원인, 그 위가 에러가 난 위치다.

```text
Traceback (most recent call last):
  File "main.py", line 3, in <module>
    print(10 / 0)
ZeroDivisionError: division by zero
       ↑ 에러 종류        ↑ 원인 설명
```

| 디버깅 방법 | 설명 |
|-------------|------|
| 에러 메시지 읽기 | 종류·위치·원인 파악 |
| `print()` 찍기 | 중간 값 확인 (`print(f"{x=}")`가 편하다) |
| 디버거 사용 | 한 줄씩 실행하며 추적 (VS Code 디버거, 코드에 `breakpoint()`) |

### 문법 에러 vs 예외

| 종류 | 언제 | 예시 |
|------|------|------|
| **문법 에러** (SyntaxError) | 실행 **전**, 코드 문법이 틀림 → 아예 실행되지 않음 | 콜론 누락 `if True`, 괄호 안 닫음 |
| **예외** (Exception) | 실행 **중**, 문법은 맞지만 실행할 수 없는 상황 | `10 / 0`, `int("abc")` |

> 예외 처리(`try`)로 다룰 수 있는 것은 **예외**뿐이다.

### 자주 만나는 내장 예외

| 예외 | 발생 상황 | 예시 |
|------|-----------|------|
| `ZeroDivisionError` | 0으로 나눔 | `10 / 0` |
| `NameError` | 정의 안 된 이름 | `print(x)` (x 없음) |
| `TypeError` | 타입이 맞지 않음 | `"1" + 1` |
| `ValueError` | 타입은 맞지만 값이 부적절 | `int("abc")` |
| `IndexError` | 인덱스 범위 초과 | `[1, 2][5]` |
| `KeyError` | 없는 딕셔너리 key | `{}["x"]` |
| `AttributeError` | 없는 속성·메서드 | `"abc".push()` |
| `FileNotFoundError` | 파일을 못 찾음 | `open("없는파일.txt")` |
| `RecursionError` | 재귀 깊이 초과 | 기저 조건 없는 재귀 |

```python
"1" + 1        # TypeError: 타입이 다름 (str + int)
int("abc")     # ValueError: 타입(str)은 맞지만 숫자로 바꿀 수 없는 값
```

### 예외의 계층 구조

> 예외도 클래스이고, **상속 관계**로 묶여 있다. 부모 예외로 `except`하면 자식 예외도 전부 잡힌다.

```text
BaseException
 ├── KeyboardInterrupt      (Ctrl+C)
 ├── SystemExit             (sys.exit())
 └── Exception              ← 일반적인 예외는 전부 여기 아래
      ├── ArithmeticError
      │    └── ZeroDivisionError
      ├── LookupError
      │    ├── IndexError
      │    └── KeyError
      ├── ValueError
      ├── TypeError
      └── OSError
           └── FileNotFoundError
```

## 예외 처리 (try · except)

> 예외가 날 수 있는 코드를 `try`에 두고, 났을 때의 처리를 `except`에 적는다. 프로그램이 **죽지 않고** 계속 실행된다.

```python
try:
    result = 10 / 0
except ZeroDivisionError:
    print("0으로 나눌 수 없습니다")   # 출력됨

print("프로그램 계속 실행")            # 죽지 않고 실행됨
```

```python
# 실용 예시: 사용자 입력 검증
try:
    age = int(input("나이: "))   # "abc" 입력 시 ValueError
    print(f"내년엔 {age + 1}세")
except ValueError:
    print("숫자를 입력하세요")
```

### 여러 예외 처리

```python
try:
    num = int(input("숫자: "))
    result = 10 / num
except ValueError:               # 숫자 변환 실패
    print("숫자가 아닙니다")
except ZeroDivisionError:        # 0 입력
    print("0으로 나눌 수 없습니다")

try:
    ...
except (ValueError, TypeError):  # 여러 예외를 튜플로 묶어 한 번에
    print("값 또는 타입 오류")
```

> ⚠️ `except`는 **위에서부터** 검사한다. 구체적인 예외를 먼저, 포괄적인 예외(`Exception`)를 뒤에 둬야 한다. 순서가 반대면 앞의 `Exception`이 전부 잡아버려 뒤의 `except`는 절대 실행되지 않는다.

### 예외 객체 받기 (as)

```python
try:
    int("abc")
except ValueError as e:        # 예외 객체를 e로 받음
    print(f"에러 발생: {e}")    # 에러 발생: invalid literal for int() with base 10: 'abc'
    print(type(e))             # <class 'ValueError'>
```

### else · finally

| 블록 | 실행 시점 |
|------|-----------|
| `try` | 예외가 날 수 있는 코드 |
| `except` | 예외가 **났을 때** |
| `else` | 예외가 **안 났을 때** |
| `finally` | 예외 여부와 **상관없이 항상** (뒷정리용) |

```python
try:
    num = int("10")
except ValueError:
    print("변환 실패")
else:
    print(f"변환 성공: {num}")   # 예외가 없으면 실행 → 변환 성공: 10
finally:
    print("항상 실행됨")          # 무조건 실행
```

> ⚠️ **`finally`에서 파일을 닫는 흔한 실수.** `open`이 실패하면 `f`가 만들어지지 않아서 `finally`의 `f.close()`가 **또 다른 에러(NameError)**를 낸다.
> ```python
> try:
>     f = open("없는파일.txt")
>     data = f.read()
> except FileNotFoundError:
>     print("파일 없음")
> finally:
>     f.close()      # ❌ open이 실패하면 f가 없다 → NameError
> ```
> 파일·연결처럼 **닫아야 하는 자원은 `with` 문**을 쓰자(아래). 실패해도 성공해도 알아서 닫아준다.

## 예외 발생시키기 (raise)

> `raise`로 예외를 **직접** 일으킬 수 있다. 함수가 처리할 수 없는 잘못된 입력을 받았을 때 쓴다.

```python
def set_age(age):
    if age < 0:
        raise ValueError("나이는 음수일 수 없습니다")
    return age

# set_age(-5)   # ValueError: 나이는 음수일 수 없습니다
```

```python
try:
    process()
except ValueError:
    print("로그 남기기")
    raise                           # 받은 예외를 그대로 다시 던지기

try:
    int("x")
except ValueError as e:
    raise RuntimeError("설정 파일 읽기 실패") from e   # 원인 예외를 연결해서 던지기
```

> 💡 `raise ... from e`를 쓰면 에러 메시지에 **원래 원인(e)**이 함께 표시되어 디버깅이 쉬워진다.

### 사용자 정의 예외

> `Exception`을 **상속**해 나만의 예외 타입을 만든다. ([12. 객체 지향 심화](12.python_oop_advanced.md)의 상속)

```python
class InsufficientBalanceError(Exception):
    def __init__(self, need):
        super().__init__(f"잔액 부족: {need}원 모자람")
        self.need = need                 # 추가 정보를 속성으로 담을 수 있다

class BankAccount:
    def __init__(self, balance):
        self.balance = balance

    def withdraw(self, amount):
        if amount > self.balance:
            raise InsufficientBalanceError(amount - self.balance)
        self.balance -= amount

acc = BankAccount(1000)
try:
    acc.withdraw(1500)
except InsufficientBalanceError as e:
    print(e, e.need)                     # 잔액 부족: 500원 모자람 500
```

### assert — 개발 중 가정 확인

```python
def average(nums):
    assert len(nums) > 0, "빈 리스트는 평균을 낼 수 없음"   # 거짓이면 AssertionError
    return sum(nums) / len(nums)
```

> ⚠️ `assert`는 **내 코드의 가정을 확인하는 용도**다. `python -O`로 실행하면 통째로 무시되므로, 사용자 입력 검증에는 `if` + `raise`를 써라.

## 예외 처리 주의사항

### 너무 넓게 잡지 마라

```python
# ❌ 나쁜 예: 모든 예외를 뭉뚱그려 무시
try:
    result = process()
except:                  # 오타(NameError)까지 다 잡아서 숨김
    pass

# ✅ 좋은 예: 예상되는 예외만 구체적으로
try:
    result = process()
except ValueError:
    print("값 오류 처리")
```

> ⚠️ 맨몸 `except:`는 `Exception`이 아니라 `BaseException`까지 잡는다. 그래서 **Ctrl+C(KeyboardInterrupt)로도 프로그램이 안 멈추는** 일이 생긴다. 잡을 예외를 명시하고, 정말 다 잡아야 하면 최소한 `except Exception as e:`로 받아 기록하자.

### EAFP vs LBYL

| 스타일 | 의미 | 방식 |
|--------|------|------|
| **EAFP** | Easier to Ask Forgiveness than Permission | 일단 실행하고, 예외로 처리 |
| **LBYL** | Look Before You Leap | 실행 전에 조건을 미리 검사 |

```python
data = {"name": "건석"}

# LBYL: 먼저 확인하고 접근
if "age" in data:
    print(data["age"])
else:
    print("키 없음")

# EAFP: 일단 시도하고 예외 처리 (파이썬에서 선호되는 편)
try:
    print(data["age"])
except KeyError:
    print("키 없음")
```

> 💡 파이썬은 **EAFP 스타일**을 선호하는 경향이 있다. 다만 예외가 자주 나는 상황(절반이 실패하는 검사 등)이라면 LBYL이 더 빠르고 읽기 쉽다.

## 파일 입출력과 with 문

### with — 자원을 알아서 정리

> `with`로 연 파일은 블록이 끝나면 **예외가 나도 자동으로 닫힌다.** 파일은 항상 `with`로 열자.

```python
with open("data.txt", "w", encoding="utf-8") as f:   # 쓰기 (없으면 만들고, 있으면 덮어씀)
    f.write("안녕\n")
    f.write("둘째 줄\n")

with open("data.txt", encoding="utf-8") as f:        # 읽기 (기본 모드 "r")
    content = f.read()            # 파일 전체를 문자열 하나로

with open("data.txt", encoding="utf-8") as f:
    for line in f:                # 한 줄씩 (큰 파일도 메모리 걱정 없음)
        print(line.rstrip("\n"))  # 줄 끝의 \n 제거
# 여기서 f는 이미 닫혀 있다 (f.closed == True)
```

| 모드 | 의미 |
|------|------|
| `"r"` | 읽기 (기본값). 파일이 없으면 `FileNotFoundError` |
| `"w"` | 쓰기. **기존 내용을 지운다** |
| `"a"` | 이어 쓰기 (끝에 추가) |
| `"x"` | 새로 만들기. 이미 있으면 에러 |
| `"b"` 추가 | 바이너리 (`"rb"`, `"wb"` — 이미지 등) |

| 읽기 메서드 | 결과 |
|-------------|------|
| `f.read()` | 전체를 문자열 하나로 |
| `f.readline()` | 한 줄 (`\n` 포함) |
| `f.readlines()` | 모든 줄을 리스트로 (`\n` 포함) |
| `for line in f:` | 한 줄씩 순회 (권장) |

> ⚠️ **`encoding="utf-8"`을 항상 적어라.** 생략하면 운영체제 기본 인코딩을 쓰는데, 한국어 Windows에서는 보통 **cp949**다. UTF-8로 저장된 한글 파일을 읽으면 `UnicodeDecodeError`가 나거나 글자가 깨진다.

```python
print("한 줄 추가", file=open("log.txt", "a", encoding="utf-8"))   # ❌ 닫지 않음

with open("log.txt", "a", encoding="utf-8") as f:
    print("한 줄 추가", file=f)   # ✅ print도 file=로 파일에 쓸 수 있다
```
