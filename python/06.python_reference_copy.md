# 🐍 파이썬 핵심 개념 — 참조 · 복사

> 파이썬의 변수는 값을 담는 상자가 아니라 **객체에 붙인 이름표**다. 이것 하나를 이해하면 "리스트를 복사했는데 원본이 같이 바뀌었다", "함수 안에서 바꿨는데 밖도 바뀌었다" 같은 일이 왜 생기는지 전부 설명된다.
>
> 💡 C++의 포인터·참조에 해당하는 개념이다. 파이썬은 주소를 직접 다루지 않을 뿐, 내부적으로는 모든 변수가 객체를 **가리키고** 있다.

---

## 변수는 이름표다

> `a = [1, 2, 3]`은 "리스트 객체를 만들고, 거기에 `a`라는 이름표를 붙인다"는 뜻이다. `b = a`는 리스트를 복사하지 않고 **같은 객체에 이름표를 하나 더** 붙인다.

```text
 a = [1, 2, 3]          a ──┐
 b = a                       ├──▶ [1, 2, 3]   (객체는 하나)
                        b ──┘
```

```python
a = [1, 2, 3]
b = a            # 같은 리스트를 가리킴 (복사 아님)

b.append(4)
print(a)         # [1, 2, 3, 4]   ← a도 바뀜!
print(a is b)    # True           ← 같은 객체
print(id(a) == id(b))   # True    (id = 객체의 고유 번호)
```

| 함수·연산 | 의미 |
|-----------|------|
| `id(x)` | 객체의 고유 번호 (CPython에선 메모리 주소) |
| `a is b` | 같은 객체인가 (`id(a) == id(b)`) |
| `a == b` | 값이 같은가 |

## 가변 객체와 불변 객체

| 구분 | 타입 | "바꾸면" 일어나는 일 |
|------|------|----------------------|
| **불변(immutable)** | `int`, `float`, `str`, `tuple`, `bool`, `None` | 객체를 바꿀 수 없어서 **새 객체를 만들고 이름표를 옮긴다** |
| **가변(mutable)** | `list`, `dict`, `set` | **객체 자체가 바뀐다** → 같은 객체를 가리키는 모든 이름에 보인다 |

```python
x = 10
y = x
x += 1           # 새 객체 11을 만들고 x 이름표를 옮김
print(y)         # 10  (y는 여전히 10을 가리킴)

a = [1]
b = a
a.append(2)      # 리스트 객체 자체를 수정
print(b)         # [1, 2]
```

> ⚠️ **`+=`는 타입에 따라 다르게 동작한다.** 리스트의 `a += [x]`는 원본을 직접 고치고(`extend`와 같음), `a = a + [x]`는 새 리스트를 만든다.
> ```python
> a = [1]; b = a
> a += [2]         # 원본 수정 → b도 [1, 2]
> a = a + [3]      # 새 리스트 [1, 2, 3]를 만들어 a만 옮김 → b는 [1, 2]
> ```

> ⚠️ 튜플은 불변이지만 **안에 든 리스트는 바뀔 수 있다.** 튜플이 바꿀 수 없는 것은 "어떤 객체들을 가리키는지"이지, 가리키는 객체의 내용이 아니다.
> ```python
> t = ([1], 2)
> t[0].append(9)   # 가능 → ([1, 9], 2)
> # t[0] = [5]     # ❌ TypeError
> ```

## 복사 (Copy)

### 얕은 복사 (Shallow Copy)

> **바깥 객체만 새로** 만들고, 안쪽의 중첩 객체는 **여전히 공유**한다.

```python
a = [[1, 2], [3, 4]]
b = a[:]              # 얕은 복사 (또는 list(a), a.copy())

b.append([5, 6])
print(a)              # [[1, 2], [3, 4]]   ← 바깥 리스트는 분리됨

b[0][0] = 99
print(a)              # [[99, 2], [3, 4]]  ← 안쪽 리스트는 공유! 같이 바뀜
```

| 얕은 복사 방법 | 예시 |
|----------------|------|
| 슬라이싱 | `b = a[:]` |
| 생성자 | `b = list(a)`, `dict(d)`, `set(s)` |
| `.copy()` | `b = a.copy()` |
| `copy` 모듈 | `b = copy.copy(a)` |

### 깊은 복사 (Deep Copy)

> 안쪽의 중첩 객체까지 **전부 새로** 복사한다. 원본과 완전히 분리된다.

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.deepcopy(a)

b[0][0] = 99
print(a)              # [[1, 2], [3, 4]]  ← 원본 영향 없음
print(b)              # [[99, 2], [3, 4]]
```

| 구분 | 바깥 객체 | 안쪽 중첩 객체 |
|------|-----------|----------------|
| 대입 `=` | 공유 | 공유 |
| 얕은 복사 | 분리 | **공유** |
| 깊은 복사 | 분리 | 분리 |

> 💡 2차원 리스트를 복사할 땐 `[row[:] for row in grid]`도 많이 쓴다. 원소가 숫자뿐이면 `deepcopy`보다 훨씬 빠르다.

## ⚠️ 2차원 리스트 함정

> `[[0] * 3] * 2`는 "0 세 개짜리 리스트 **하나**"를 만든 뒤 그 **이름표를 두 번** 담는다. 그래서 한 행을 고치면 모든 행이 바뀐다.

```python
grid = [[0] * 3] * 2
grid[0][0] = 1
print(grid)           # [[1, 0, 0], [1, 0, 0]]  ← 두 행이 같은 객체!

grid = [[0] * 3 for _ in range(2)]   # ✅ 행마다 새 리스트를 만든다
grid[0][0] = 1
print(grid)           # [[1, 0, 0], [0, 0, 0]]
```

> 💡 `[0] * 3`은 괜찮다. 숫자는 불변이라 공유해도 문제가 없기 때문이다. **가변 객체(리스트)를 `*`로 복제할 때만** 문제가 된다.

## 함수 인자 전달 — 객체의 참조가 넘어간다

> 함수를 호출하면 인자로 준 **객체에 대한 참조(이름표)**가 매개변수에 붙는다. 그래서 결과는 두 가지로 갈린다.
> - 매개변수로 **객체를 수정**하면 (`lst.append`) → 호출한 쪽에서도 보인다
> - 매개변수에 **다른 값을 대입**하면 (`lst = [...]`) → 함수 안의 이름표만 옮겨질 뿐 바깥은 그대로다

```python
def modify(lst):
    lst.append(4)          # 객체 수정 → 바깥에 영향

def rebind(lst):
    lst = [0]              # 이름표만 옮김 → 바깥은 그대로

nums = [1, 2, 3]
modify(nums)
rebind(nums)
print(nums)                # [1, 2, 3, 4]

def inc(n):
    n += 1                 # int는 불변 → 새 객체, 바깥 영향 없음

k = 1
inc(k)
print(k)                   # 1
```

> 💡 함수가 인자로 받은 리스트를 바꾸면 호출한 쪽이 놀랄 수 있다. 원본을 지켜야 하면 함수 안에서 `lst = lst[:]`로 복사해서 쓰거나, 새 리스트를 만들어 `return`하자.

> ⚠️ 같은 원리로 **기본값을 `[]`로 둔 매개변수는 호출 사이에 공유된다.** ([08. 함수](08.python_functions.md)의 가변 기본값 함정 참고)
