## 스코프 (Scope)

> **스코프** : 변수에 접근할 수 있는 범위. 파이썬은 이름을 **LEGB 순서**로 찾는다.

| 약자 | 범위 | 설명 |
|------|------|------|
| **L**ocal | 지역 | 지금 실행 중인 함수 안 |
| **E**nclosing | 둘러싼 함수 | 중첩 함수에서 바깥 함수 |
| **G**lobal | 전역 | 모듈(파일) 최상단 |
| **B**uilt-in | 내장 | 파이썬 기본 제공 (`print`, `len` 등) |

```python
x = "global"          # 전역 변수

def func():
    x = "local"       # 지역 변수 (전역 x와 별개)
    print(x)          # local

func()
print(x)              # global  (전역은 그대로)
```

### global

> 함수 안에서 **전역 변수에 새 값을 대입**하려면 `global`로 선언해야 한다.

```python
count = 0

def increment():
    global count      # 전역 count를 쓰겠다고 선언
    count += 1

increment()
print(count)          # 1
```

선언 없이 함수 안에서 전역 변수에 **대입**하면 에러가 난다.

```python
count = 0

def bad():
    count += 1        # ❌ UnboundLocalError
    # 대입이 있으면 count를 지역 변수로 보는데, 아직 값이 없다
```

> 💡 **읽기만 하거나, 객체를 수정만 하는 건** `global` 없이 된다. `global`이 필요한 건 이름에 **새 값을 대입**할 때뿐이다.
> ```python
> items = []
> def add(x):
>     items.append(x)   # ✅ 대입이 아니라 객체 수정 → global 불필요
> ```

> ⚠️ `global`은 코드 흐름을 추적하기 어렵게 만든다. 가급적 **인자로 받고 `return`으로 돌려주는** 방식을 쓰자.

### nonlocal · 클로저

> 중첩 함수에서 **바깥 함수의 변수**에 대입하려면 `nonlocal`을 쓴다. 안쪽 함수가 바깥 함수의 변수를 기억한 채로 밖에 나와 계속 쓰이는 것을 **클로저(closure)**라고 한다.

```python
def make_counter():
    cnt = 0
    def counter():
        nonlocal cnt      # 바깥 함수의 cnt를 쓰겠다
        cnt += 1
        return cnt
    return counter        # 함수 자체를 반환

c = make_counter()
c()        # 1
c()        # 2   (make_counter가 끝났어도 cnt를 기억함)
```

> 💡 파이썬에서 함수는 **값(일급 객체)**이다. 변수에 담고, 인자로 넘기고, 반환할 수 있다. `sorted(words, key=len)`처럼 함수 `len`을 인자로 넘기는 것도 같은 원리다.

## 재귀 함수 (Recursive Function)

> **자기 자신을 호출**하는 함수. 반드시 **종료 조건(기저 조건)**이 있어야 한다.

```python
def factorial(n):
    if n <= 1:                    # 기저 조건 (종료점)
        return 1
    return n * factorial(n - 1)   # 더 작은 문제로 자기 자신 호출

factorial(5)    # 120  (5 * 4 * 3 * 2 * 1)
```

| 요소 | 설명 |
|------|------|
| 기저 조건 | 재귀를 멈추는 조건 (필수) |
| 재귀 호출 | 더 작은 문제로 자기 자신 호출 |

> ⚠️ 기저 조건이 없으면 무한 재귀 → `RecursionError`가 난다.

> ⚠️ **기본 재귀 깊이 한도는 1000이다.** 기저 조건이 맞아도 깊이가 1000을 넘으면 `RecursionError`다. 깊은 재귀가 꼭 필요하면 한도를 올리거나, 반복문과 스택으로 바꾼다.
> ```python
> import sys
> sys.setrecursionlimit(10 ** 6)   # 재귀 한도 올리기
> ```

> 💡 같은 인자로 여러 번 호출되는 재귀(피보나치 등)는 `functools.lru_cache`로 결과를 기억하면 빨라진다. ([10. 모듈 · 표준 라이브러리](10.python_modules.md))

## 람다 표현식 (Lambda)

> 이름 없이 **한 줄로 정의**하는 작은 함수. `lambda 매개변수: 반환할_식`

```python
def add(a, b):
    return a + b

add2 = lambda a, b: a + b    # 위와 같은 동작
add2(3, 5)                   # 8
```

주로 `sorted`, `map`, `filter`, `max` 등에 **한 번 쓰고 버릴 함수**로 넘길 때 쓴다.

```python
nums = [3, 1, 4, 1, 5]

sorted(nums, key=lambda x: -x)                  # [5, 4, 3, 1, 1]  (내림차순)
list(map(lambda x: x * 2, nums))                # [6, 2, 8, 2, 10]
list(filter(lambda x: x > 2, nums))             # [3, 4, 5]
max(["aa", "b", "ccc"], key=lambda s: len(s))   # 'ccc'
```

| 구분 | `def` 함수 | `lambda` |
|------|------------|----------|
| 이름 | 있음 | 없음 (익명) |
| 길이 | 여러 줄 가능 | 식 하나 |
| 용도 | 재사용·복잡한 로직 | 간단한 일회용 함수 |

> ⚠️ 람다는 **식 하나**만 담을 수 있다(`if` 문, `for` 문 불가). 그리고 `add2 = lambda ...`처럼 이름에 담아 쓸 거라면 `def`가 낫다는 게 PEP 8의 권고다.

## 내장 함수 (Built-in Function)

> `import` 없이 바로 쓸 수 있는 함수들.

| 함수 | 설명 | 예시 | 결과 |
|------|------|------|------|
| `len()` | 길이 | `len([1, 2, 3])` | `3` |
| `type()` / `isinstance()` | 타입 확인 | `isinstance(3, int)` | `True` |
| `sum()` | 합계 | `sum([1, 2, 3])` | `6` |
| `max()` / `min()` | 최댓값 / 최솟값 (`key=` 가능) | `max([3, 1, 4])` | `4` |
| `abs()` | 절댓값 | `abs(-5)` | `5` |
| `round()` | 반올림 (짝수 쪽 주의) | `round(3.14159, 2)` | `3.14` |
| `divmod()` | 몫과 나머지 | `divmod(17, 5)` | `(3, 2)` |
| `sorted()` / `reversed()` | 정렬 / 역순 | `sorted([3, 1, 2])` | `[1, 2, 3]` |
| `any()` / `all()` | 하나라도 참 / 모두 참 | `any([0, 0, 1])` | `True` |
| `enumerate()` / `zip()` | 인덱스 붙이기 / 짝짓기 | ([07. 제어문](07.python_control_flow.md)) | |
| `map()` / `filter()` | 전부 변환 / 조건으로 거르기 | (아래) | |

```python
nums = [1, 2, 3]
list(map(str, nums))                    # ['1', '2', '3']  모든 원소에 함수 적용
list(filter(lambda x: x > 1, nums))     # [2, 3]           조건을 만족하는 것만

all(x > 0 for x in nums)                # True  (모두 양수인가)
any(x > 2 for x in nums)                # True  (2보다 큰 게 하나라도 있나)
```

> 💡 `map`/`filter`는 컴프리헨션으로도 쓸 수 있다. `[str(x) for x in nums]`, `[x for x in nums if x > 1]`. 어느 쪽이든 읽기 쉬운 쪽을 쓰면 된다.

## 이터레이터와 제너레이터

### 이터레이터 — 한 번 쓰면 끝

> `map`, `filter`, `zip`, `enumerate`의 결과는 리스트가 아니라 **이터레이터**다. 값을 미리 다 만들어두지 않고, 요청할 때마다 **하나씩** 꺼내 준다. 그래서 `list()`로 바꿔야 내용이 보이고, **한 번 다 꺼내면 비어 버린다.**

```python
it = map(int, ["1", "2"])
print(it)          # <map object at ...>  (내용이 바로 안 보임)
print(list(it))    # [1, 2]
print(list(it))    # []   ← 이미 다 꺼냄!

it = iter([10, 20])
next(it)           # 10   (next로 하나씩 꺼내기)
next(it)           # 20
# next(it)         # ❌ StopIteration (더 없음)
```

> ⚠️ 이터레이터를 두 번 쓰려면 처음에 `list()`로 바꿔 담아 두자.

### 제너레이터 — yield로 하나씩 만들기

> 함수 안에 `return` 대신 **`yield`**를 쓰면 제너레이터가 된다. 호출할 때마다 `yield` 지점까지 실행하고 값을 내준 뒤 **그 자리에서 멈춰 기다린다.**

```python
def squares(n):
    for i in range(n):
        yield i * i      # 값을 하나 내주고 여기서 멈춤

g = squares(4)
next(g)                  # 0
list(g)                  # [1, 4, 9]  (남은 것들)

for v in squares(3):     # for문에서 바로 쓰는 게 일반적
    print(v)             # 0 → 1 → 4
```

**제너레이터 표현식** — 컴프리헨션의 `[ ]`를 `( )`로 바꾸면 리스트를 만들지 않고 값을 하나씩 흘려보낸다.

```python
sum(x * x for x in range(4))         # 14  (함수 인자로 줄 땐 괄호 한 번만)
total = sum(x for x in range(10**7)) # 천만 개짜리 리스트를 만들지 않음
```

> 💡 **왜 쓰나:** 값을 한꺼번에 메모리에 올리지 않아서, 아주 큰 데이터나 끝없이 이어지는 데이터를 다룰 때 메모리를 거의 쓰지 않는다. 파일을 한 줄씩 읽는 `for line in f:`도 같은 방식이다.
