## 매직 메서드 (Magic Method)

> `__이름__` 형태의 **특수 메서드**. 특정 상황에서 파이썬이 **자동으로 호출**한다. (던더 메서드라고도 한다)

```python
class Point:
    def __init__(self, x, y):      # 생성 시
        self.x = x
        self.y = y

    def __repr__(self):            # 개발자용 표현 (리스트 안, 디버깅 출력)
        return f"Point({self.x}, {self.y})"

    def __str__(self):             # 사용자용 표현 (print, str)
        return f"({self.x}, {self.y})"

    def __add__(self, other):      # + 연산
        return Point(self.x + other.x, self.y + other.y)

    def __eq__(self, other):       # == 비교
        return (self.x, self.y) == (other.x, other.y)

    def __lt__(self, other):       # < 비교 → sorted가 이걸 쓴다
        return (self.x, self.y) < (other.x, other.y)

p1, p2 = Point(1, 2), Point(3, 4)
print(p1)              # (1, 2)              ← __str__
print([p1, p2])        # [Point(1, 2), Point(3, 4)]  ← 리스트 안에선 __repr__
print(p1 + p2)         # (4, 6)              ← __add__
print(p1 == Point(1, 2))          # True     ← __eq__
print(sorted([p2, p1]))           # [Point(1, 2), Point(3, 4)]  ← __lt__
```

| 매직 메서드 | 호출 시점 |
|-------------|-----------|
| `__init__` | 객체 생성 |
| `__str__` | `print()`, `str()` |
| `__repr__` | 대화형 출력, 리스트 안의 출력, `repr()` (`__str__`이 없으면 대신 쓰임) |
| `__len__` | `len()` |
| `__eq__` / `__lt__` | `==` / `<` 비교 (`__lt__`가 있으면 정렬 가능) |
| `__add__` | `+` 연산 |
| `__getitem__` | `obj[key]` 인덱싱 |
| `__contains__` | `x in obj` |

> 💡 `__repr__`부터 만들자. `__str__`이 없으면 `print`도 `__repr__`을 쓰기 때문에 하나로 양쪽이 해결된다.

> ⚠️ **`__eq__`를 정의하면 그 객체는 해시 불가능해진다**(세트 원소·딕셔너리 key로 쓸 수 없음). 키로도 쓰려면 `__hash__`도 함께 정의하거나, 아래의 `@dataclass(frozen=True)`를 쓴다.

## 데코레이터 (Decorator)

> 기존 함수를 **감싸서 기능을 덧붙이는** 문법. `@데코레이터`를 함수 위에 붙이면 `함수 = 데코레이터(함수)`와 같다.

```python
from functools import wraps

def log(func):
    @wraps(func)                       # 원래 함수의 이름·설명을 유지
    def wrapper(*args, **kwargs):      # 어떤 인자든 그대로 받아서
        print(f"→ {func.__name__}{args} 호출")
        result = func(*args, **kwargs) # 원래 함수 실행
        print(f"← 결과 {result}")
        return result                  # 결과도 돌려줘야 한다
    return wrapper

@log
def add(a, b):
    return a + b

add(2, 3)
# → add(2, 3) 호출
# ← 결과 5
```

> ⚠️ `wrapper`가 `*args, **kwargs`를 받지 않거나 `return`을 빠뜨리면, 꾸며진 함수가 인자를 못 받거나 `None`을 반환하게 된다. 위 형태를 기본 틀로 외워두자.

> 💡 `@classmethod`, `@staticmethod`, `@property`, `@lru_cache`, `@dataclass`가 대표적인 내장 데코레이터다.

## 캡슐화 — 속성 보호

### `_` 와 `__` 이름 규칙

> 파이썬엔 C++의 `private` 같은 **강제 접근 제한이 없다.** 대신 이름 규칙으로 의도를 표시한다.

| 이름 | 의미 | 바깥에서 접근 |
|------|------|---------------|
| `name` | 공개 | 자유롭게 |
| `_name` | "내부용이니 건드리지 마세요" (관례) | 가능하지만 쓰지 않는 게 약속 |
| `__name` | 이름이 `_클래스명__name`으로 바뀜(**name mangling**) | `obj.__name`으로는 안 됨 |

```python
class Account:
    def __init__(self, balance):
        self._note = "내부용"
        self.__balance = balance

acc = Account(100)
acc._note              # '내부용' (되긴 한다)
# acc.__balance        # ❌ AttributeError
acc._Account__balance  # 100     (바뀐 이름으로는 접근 가능 — 완전한 차단은 아님)
```

> 💡 `__name`의 진짜 목적은 숨기기보다 **자식 클래스와 이름이 충돌하지 않게** 하는 것이다. 보통은 `_name`으로 충분하다.

### @property — 메서드를 속성처럼

> 메서드를 **괄호 없이 속성처럼** 읽게 만든다. `@이름.setter`를 함께 쓰면 값을 넣을 때 **검증**을 끼워 넣을 수 있다.

```python
class Account:
    def __init__(self, balance):
        self._balance = balance

    @property
    def balance(self):              # 읽기: acc.balance
        return self._balance

    @balance.setter
    def balance(self, value):       # 쓰기: acc.balance = 값
        if value < 0:
            raise ValueError("잔액은 음수가 될 수 없음")
        self._balance = value

acc = Account(100)
acc.balance = 50       # setter 호출
print(acc.balance)     # 50  (괄호 없이)
# acc.balance = -1     # ❌ ValueError
```

> 💡 처음엔 그냥 `self.balance`로 공개해 두고, 나중에 검증이 필요해지면 `@property`로 바꾸면 된다. 사용하는 쪽 코드(`acc.balance`)는 바뀌지 않는다.

## 상속 (Inheritance)

### 상속 기본

> 기존 클래스(부모)의 속성·메서드를 **물려받아** 새 클래스(자식)를 만든다.

```python
class Animal:                   # 부모 클래스
    def __init__(self, name):
        self.name = name
    def eat(self):
        print(f"{self.name}가 먹는다")

class Dog(Animal):              # Animal을 상속
    def bark(self):
        print("멍멍")

d = Dog("바둑이")
d.eat()     # 바둑이가 먹는다   (부모에게서 물려받음)
d.bark()    # 멍멍             (자식 고유)

issubclass(Dog, Animal)   # True
isinstance(d, Animal)     # True  (자식 인스턴스는 부모 타입이기도 하다)
```

| 용어 | 다른 이름 |
|------|-----------|
| 부모 클래스 | 상위 클래스, 슈퍼 클래스 |
| 자식 클래스 | 하위 클래스, 서브 클래스 |

### super() — 부모의 메서드 호출

> 자식에서 **부모 클래스의 메서드**를 부를 때 쓴다. 주로 `__init__`에서 부모 초기화를 맡길 때 쓴다.

```python
class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)    # 부모의 __init__ 호출 → self.name 설정
        self.breed = breed        # 자식 고유 속성 추가

d = Dog("바둑이", "진돗개")
print(d.name, d.breed)    # 바둑이 진돗개
```

> 💡 `Animal.__init__(self, name)`처럼 부모 이름을 직접 써도 되지만, `super()`를 쓰면 부모 클래스 이름이 바뀌어도 고칠 필요가 없고 다중 상속에서도 MRO 순서대로 올바르게 호출된다.

> ⚠️ 자식이 `__init__`을 새로 정의하면 부모의 `__init__`은 **자동으로 불리지 않는다.** `super().__init__(...)`을 빠뜨리면 부모가 만들던 속성(`self.name`)이 없어 `AttributeError`가 난다.

### 메서드 오버라이딩과 다형성

> 물려받은 메서드를 자식이 **같은 이름으로 다시 정의**하는 것. 같은 `speak()` 호출이 객체에 따라 다르게 동작한다(**다형성**).

```python
class Animal:
    def speak(self):
        return "..."

class Dog(Animal):
    def speak(self):
        return "멍멍"

class Cat(Animal):
    def speak(self):
        return "야옹"

for a in [Dog(), Cat()]:
    print(a.speak())    # 멍멍 → 야옹
```

> 💡 **덕 타이핑:** 파이썬은 상속 관계가 없어도 **같은 이름의 메서드만 있으면** 똑같이 호출할 수 있다. "오리처럼 걷고 꽥꽥거리면 오리다." 타입보다 **할 수 있는 일**을 본다.

### 다중 상속과 MRO

> 여러 부모를 동시에 상속할 수 있다. 메서드를 찾는 순서는 **MRO(Method Resolution Order)**를 따른다.

```python
class Flyer:
    def move(self): return "난다"

class Swimmer:
    def move(self): return "헤엄친다"
    def swim(self): return "물속"

class Duck(Flyer, Swimmer):   # 왼쪽 부모가 먼저
    pass

d = Duck()
d.move()                      # '난다'   (Flyer가 먼저)
d.swim()                      # '물속'
[c.__name__ for c in Duck.__mro__]   # ['Duck', 'Flyer', 'Swimmer', 'object']
```

### 추상 클래스 (ABC)

> 자식이 **반드시 구현해야 할 메서드**를 정해 두는 부모 클래스. 추상 클래스 자체로는 인스턴스를 만들 수 없다.

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...           # 자식이 반드시 구현

class Square(Shape):
    def __init__(self, side):
        self.side = side
    def area(self):
        return self.side ** 2

# Shape()                         # ❌ TypeError: 추상 메서드가 있어 생성 불가
Square(3).area()                  # 9
```

## dataclass — 데이터 담는 클래스를 짧게 (3.7+)

> 데이터를 담는 게 주목적인 클래스는 `@dataclass`를 붙이면 `__init__`, `__repr__`, `__eq__`를 **자동으로** 만들어 준다.

```python
from dataclasses import dataclass, field

@dataclass
class Student:
    name: str
    score: int = 0                            # 기본값
    tags: list = field(default_factory=list)  # 가변 기본값은 이렇게

s = Student("kim", 90)
print(s)                          # Student(name='kim', score=90, tags=[])
print(s == Student("kim", 90))    # True

@dataclass(order=True)            # <, > 비교 자동 생성 → 정렬 가능 (필드 순서대로 비교)
class P:
    x: int
    y: int

sorted([P(2, 1), P(1, 9)])        # [P(x=1, y=9), P(x=2, y=1)]

@dataclass(frozen=True)           # 불변 → 수정 불가, 해시 가능(세트·딕셔너리 key로 사용)
class Pos:
    r: int
    c: int
```
