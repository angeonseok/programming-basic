# 🔷 07. 참조와 메모리 관리

> [06. 포인터](06.cpp_pointer.md)에 이어, 변수의 별명인 **참조**, 변수가 사는 **메모리 영역과 수명**, 메모리를 안전하게 관리하는 **스마트 포인터 · RAII · 이동**을 다룬다.

## 참조

### 참조 변수

> **참조(reference)** : 기존 변수의 **별명(alias)**. `&`를 타입에 붙여 선언하며, 한 번 묶이면 그 변수 그 자체처럼 동작한다.

```cpp
int x = 5;
int& ref = x;       // ref는 x의 별명

ref = 10;
cout << x;          // 10  (ref를 바꾸면 x가 바뀜)
```

> ⚠️ 참조는 **선언 시 반드시 초기화**해야 하고, 한 번 묶이면 **다른 변수로 바꿀 수 없다**(rebind 불가).

> 💡 참조는 내부적으로는 주소를 들고 있지만, 문법상 변수 그 자체처럼 쓰게 해주는 장치다. "**절대 null이 아니고, 다른 대상으로 바뀌지 않는 포인터**"라고 생각하면 된다.

### 포인터 vs 참조

| | 포인터 (`int* p`) | 참조 (`int& r`) |
|--|-------------------|------------------|
| 초기화 | 나중에 가능 | 선언 시 필수 |
| 재지정 | 다른 대상 가리키기 가능 | 불가 (한 대상 고정) |
| null | 가능 (`nullptr`) | 불가 (항상 유효) |
| 문법 | `*p`로 역참조 | 변수처럼 바로 사용 |

| 상황 | 쓸 것 |
|------|-------|
| 함수에서 원본 수정 | `T&` |
| 큰 데이터 읽기 전용 전달 | `const T&` |
| 없을 수도 있는 대상 | `T*` (`nullptr` 가능) 또는 `optional` ([04. 함수](04.cpp_functions.md)) |
| 가리키는 대상을 바꿔 가며 이동 (연결 리스트 순회) | `T*` |

> 💡 **참조가 중요한 이유:** 함수에 큰 컨테이너를 넘길 때 `vector<int>& v`(수정) 또는 `const vector<int>& v`(읽기 전용)로 넘기면 **복사 없이** 원본을 다룬다. 값 복사는 성능 저하의 숨은 원인이다. ([04. 함수](04.cpp_functions.md)의 "참조 전달" 참고)

```cpp
void print(const vector<int>& v) {   // 복사 안 함, 수정 불가
    for (int x : v) cout << x;
}

vector<int> v = {1, 2, 3};
for (int& x : v) x *= 2;             // 범위 기반 for에서도 참조로 원본 수정 → {2, 4, 6}
```

### const 참조는 임시값도 받는다

```cpp
// int& r = 5;           // ❌ 일반 참조는 이름 있는 변수만 받는다
const int& r = 5;        // ✅ const 참조는 임시값(리터럴, 식의 결과)도 받는다

void print(const string& s);
print("hello");          // ✅ "hello"로 임시 string을 만들어 넘김

void edit(string& s);
// edit("hello");        // ❌ 컴파일 에러
```

> 💡 그래서 읽기 전용 매개변수는 `const T&`가 가장 범용적이다. 변수, 리터럴, 식의 결과를 모두 복사 없이 받는다.

### lvalue · rvalue (값의 종류)

> 식의 값은 크게 두 종류다. 이 구분이 참조와 **이동**(아래)의 규칙을 정한다.

| 종류 | 뜻 | 예 | `&`로 주소 얻기 |
|------|----|----|------------------|
| lvalue | 이름이 있고 계속 존재하는 값 | `x`, `v[0]`, `*p` | 가능 |
| rvalue | 식이 끝나면 사라지는 임시값 | `5`, `x + 1`, `string("a")`, 값으로 반환된 결과 | 불가 |

| 참조 | 받을 수 있는 것 |
|------|-----------------|
| `T&` | lvalue만 |
| `const T&` | lvalue, rvalue 모두 |
| `T&&` (rvalue 참조, C++11) | rvalue만 → "곧 사라질 값이니 내용물을 가져가도 된다" |

## 메모리 영역과 변수의 수명

> 변수는 **어디에 선언했느냐**에 따라 저장되는 영역과 **살아 있는 기간(수명)**이 달라진다.

| 영역 | 무엇이 | 수명 | 특징 |
|------|--------|------|------|
| 코드 | 컴파일된 함수 | 프로그램 전체 | 읽기 전용 |
| 정적(데이터) | 전역 변수, `static` 변수, 문자열 리터럴 | 프로그램 시작 ~ 끝 | **자동 0 초기화**, 큰 배열도 OK |
| 스택 | 지역 변수, 매개변수 | 블록(`{}`) 시작 ~ 끝 | 빠름, **크기 제한(1~8MB)**, 자동 해제 |
| 힙 | `new`로 할당한 것 | `delete`할 때까지 | 큼, 직접 관리 (또는 `vector`·스마트 포인터가 관리) |

```cpp
int g[1'000'000];               // 정적: 프로그램 내내 존재, 전부 0

void f() {
    int a = 5;                  // 스택: f가 끝나면 사라짐
    static int calls = 0;       // 정적: f가 끝나도 값 유지 (처음 한 번만 초기화)
    calls++;                    // f를 세 번 부르면 1, 2, 3
    int* p = new int(5);        // p(주소, 8바이트)는 스택에, *p(int)는 힙에
    delete p;                   // 힙 메모리는 직접 반납
}                               // 여기서 a, p 소멸 (calls는 유지)
```

> 💡 [부록 B. 알고리즘 구현 패턴](B.cpp_algorithm_patterns.md)에서 "큰 배열은 전역에 두라"고 한 이유가 이 표다. 전역은 정적 영역이라 스택 한도와 무관하고 자동으로 0이 된다. `int arr[10000000]`을 함수 안에 두면 스택 한도를 넘겨 죽는다. **전역**으로 빼거나 `vector`(내부적으로 힙 사용)를 써라.

### 스택과 함수 호출

> 함수를 호출할 때마다 스택에 그 함수의 지역 변수 묶음(**스택 프레임**)이 쌓이고, 함수가 끝나면 치워진다.

```text
main 호출   →  [main]
f(3) 호출   →  [main][f(3)]
f(2) 호출   →  [main][f(3)][f(2)]
f(2) 끝     →  [main][f(3)]          ← f(2)의 지역 변수는 이제 없음
```

> 💡 재귀가 깊어지면 프레임이 계속 쌓여 스택 한도를 넘는다. 이것이 **스택 오버플로**다([04. 함수](04.cpp_functions.md)의 재귀 참고).

> ⚠️ 그래서 **지역 변수의 주소나 참조를 반환하면 안 된다.** 함수가 끝나는 순간 그 프레임이 치워져서, 반환된 주소는 이미 사라진 변수를 가리킨다([04. 함수](04.cpp_functions.md)의 "참조 반환 주의").
> ```cpp
> int* bad() { int x = 5; return &x; }   // ❌ 댕글링 포인터
> ```

### 동적 할당 (new / delete)

> 실행 중에 힙에서 메모리를 직접 잡고(`new`) 직접 반납(`delete`)한다.

```cpp
int* p = new int(42);   // 힙에 int 하나 할당
cout << *p;             // 42
delete p;               // 반납 (필수!)

int* arr = new int[5];  // 배열 할당
delete[] arr;           // 배열은 delete[] 로 반납

string* sp = new string("hello");   // 객체도 가능: 생성자가 불림
cout << sp->size();                  // 5
delete sp;                           // 소멸자가 불리고 메모리 반납
```

> ⚠️ `new`한 건 반드시 `delete`. 배열은 `delete[]`. 짝을 안 맞추면 **메모리 누수**나 정의되지 않은 동작이 생긴다. 그래서 현대 C++에선 raw `new`를 피하고 `vector`·스마트 포인터를 쓴다.

### 흔한 메모리 버그

| 버그 | 예시 | 결과 |
|------|------|------|
| 초기화 안 한 포인터 | `int* p; *p = 1;` | 아무 곳이나 덮어씀 → RE 또는 이상한 값 |
| 널 포인터 역참조 | `Node* p = nullptr; p->val;` | 즉시 RE (segfault) |
| 댕글링 포인터 | `delete p; *p = 1;` / 지역 변수 주소 반환 | 이미 반납한 메모리 사용 → 예측 불가 |
| 이중 해제 | `delete p; delete p;` | RE |
| `new[]`/`delete` 짝 불일치 | `int* a = new int[5]; delete a;` | 정의되지 않은 동작 |
| 메모리 누수 | `new` 후 `delete` 안 함 | 당장은 멀쩡, 오래 돌면 메모리 부족 |
| 범위 밖 접근 | `arr[n]`, `arr[-1]` | 옆 변수 오염 또는 RE |

> 💡 `delete p;` 뒤에 `p = nullptr;`를 해두면 이중 해제·댕글링을 조금 막을 수 있다(`delete nullptr`는 아무 일도 하지 않는다). 하지만 근본 해결은 **raw `new`/`delete`를 쓰지 않는 것**, 즉 `vector`와 스마트 포인터다. 이런 버그는 [15. 예외 처리](15.cpp_exception.md)의 디버깅 옵션(`-fsanitize=address`)이 위치를 정확히 알려준다.

## 스마트 포인터 — 소유권을 타입으로 표현

> `new`/`delete`를 손으로 맞추는 건 실수가 잦다. **스마트 포인터**는 포인터를 감싼 객체로, 자신이 사라질 때 **가리키던 메모리를 자동으로 `delete`**한다. (`#include <memory>`)

### unique_ptr — 혼자 소유

```cpp
#include <memory>
{
    unique_ptr<int> p = make_unique<int>(5);   // C++14
    cout << *p;                                 // 5  (일반 포인터처럼 *, -> 사용)

    // unique_ptr<int> q = p;                   // ❌ 복사 불가 (소유자는 하나뿐)
    unique_ptr<int> q = std::move(p);           // ✅ 소유권 이전 → 이제 p는 비어 있음(nullptr)
    if (!p) cout << "p는 비었음\n";
}   // 블록 끝 → q가 사라지며 자동으로 delete
```

트리를 `unique_ptr`로 만들면 해제 코드가 필요 없다.

```cpp
struct TreeNode {
    int val;
    unique_ptr<TreeNode> left, right;   // 자식을 "소유"
    TreeNode(int v) : val(v) {}
};

void inorder(const TreeNode* node) {     // 읽기만 하므로 소유권 없이 raw 포인터로 받음
    if (node == nullptr) return;
    inorder(node->left.get());           // .get() = 안에 든 raw 포인터
    cout << node->val << " ";
    inorder(node->right.get());
}

auto root = make_unique<TreeNode>(2);
root->left = make_unique<TreeNode>(1);
root->right = make_unique<TreeNode>(3);
inorder(root.get());   // 1 2 3
// delete 불필요: root가 사라지면 자식들도 연쇄적으로 자동 해제
```

> 💡 "**`unique_ptr` = 소유, raw 포인터·참조 = 빌려 보기**"로 역할을 나누는 게 현대 C++의 관례다. 함수가 대상을 읽기만 한다면 소유권(`unique_ptr`)을 넘기지 말고 `.get()`이나 참조로 넘긴다.

### shared_ptr — 여럿이 공유

```cpp
shared_ptr<int> a = make_shared<int>(10);
shared_ptr<int> b = a;            // 복사 가능: 같은 대상을 함께 소유
cout << a.use_count();            // 2  (소유자 수)
b.reset();                        // b가 소유를 포기 → 1
// 마지막 소유자가 사라질 때 delete
```

> ⚠️ 두 객체가 서로를 `shared_ptr`로 가리키면(**순환 참조**) 소유자 수가 0이 되지 않아 영원히 해제되지 않는다. 한쪽을 `weak_ptr`(소유하지 않고 지켜보기만 하는 포인터)로 바꿔 순환을 끊는다.

| 스마트 포인터 | 소유 | 복사 | 언제 |
|---------------|------|------|------|
| `unique_ptr` | 하나 | ❌ (이동만) | **기본 선택.** 동적 객체가 필요하면 먼저 이것 |
| `shared_ptr` | 여럿 (참조 카운트) | ✅ | 소유자가 정말 여럿일 때 |
| `weak_ptr` | 소유 안 함 | ✅ | `shared_ptr`의 순환 끊기 |

> 💡 `make_unique`는 C++14, `make_shared`는 C++11부터 있다. `new`를 직접 쓰지 말고 이 함수들로 만들자.

## RAII — 왜 vector면 충분한가

> **RAII (Resource Acquisition Is Initialization)** : 자원을 객체가 쥐고, **객체가 사라질 때 소멸자가 자동으로 반납**하는 C++의 핵심 패턴. 스마트 포인터도 RAII다.

```cpp
{
    vector<int> v(1000000);   // 내부적으로 힙에 메모리 할당
    // ... 사용 ...
}   // 블록 끝 → v 소멸 → 메모리 자동 반납
```

> 💡 **우리가 쓰는 `vector`·`string`이 전부 RAII다.** 내부적으로 힙 메모리를 잡지만 범위를 벗어나면 알아서 반납한다. 그래서 일반적인 코드에선 raw `new`/`delete`를 직접 쓸 일이 거의 없다. 컨테이너가 다 해준다.

## 이동 (move) — 복사 대신 넘겨주기

> C++11부터 객체를 **복사하지 않고 내부 자원(힙 메모리)만 넘겨주는** "이동"이 생겼다. `std::move(x)`는 "x는 이제 안 쓸 테니 내용물을 가져가도 된다"는 표시다. (`#include <utility>`)

```cpp
vector<int> a(1'000'000, 1);
vector<int> b = a;              // 복사: 원소 100만 개를 새로 복사 (O(n))
vector<int> c = std::move(a);   // 이동: a의 메모리를 c가 넘겨받음 (O(1))

vector<string> names;
string s = "아주 긴 문자열...";
names.push_back(std::move(s));  // s를 복사하지 않고 벡터 안으로 이동
```

> 💡 `std::move` 자체는 아무것도 옮기지 않는다. `x`를 **rvalue(`T&&`)로 바꿔 주는 캐스팅**일 뿐이다. 그 rvalue를 받은 이동 생성자가 내부 포인터만 넘겨받는 방식으로 내용물을 가져간다. `vector`의 이동이 O(1)인 이유는 원소가 아니라 **힙을 가리키는 포인터 하나만** 옮기기 때문이다.

> ⚠️ 이동한 뒤의 원본(`a`, `s`)은 "유효하지만 내용은 정해지지 않은" 상태다. 실제로는 보통 비어 있지만 그렇다고 가정하지 말고, **새 값을 대입하기 전엔 쓰지 마라.**

> 💡 함수가 지역 변수를 반환할 때는 `return std::move(v);`라고 쓰지 말고 그냥 `return v;`라고 써라. 컴파일러가 알아서 복사 생략·이동을 해주며, `std::move`를 붙이면 오히려 복사 생략을 방해한다([04. 함수](04.cpp_functions.md) 참고).

## 정리 — 무엇을 쓸까

| 하고 싶은 것 | 쓸 것 |
|--------------|-------|
| 값 하나 저장 | 그냥 변수 (`int x`) |
| 함수에서 원본 수정 | 참조 `T&` |
| 큰 데이터를 읽기 전용으로 전달 | `const T&` |
| 크기가 바뀌는 배열 | `vector` |
| 동적으로 만든 객체를 혼자 소유 | `unique_ptr` |
| 여럿이 함께 소유 | `shared_ptr` |
| 소유하지 않고 가리키기 (없을 수도 있음) | raw 포인터 `T*` |
| 직접 `new` / `delete` | 거의 쓰지 않는다 |
