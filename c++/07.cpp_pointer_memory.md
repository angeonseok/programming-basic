# 🔷 C++ 기초 문법 — 포인터 · 참조 · 메모리

> 파이썬은 메모리 주소·할당을 전부 숨기고 GC가 관리했다. C++은 **메모리를 직접 다룬다.**
>
> 💡 **코테 관점:** 실전에선 raw 포인터·`new`/`delete`를 거의 쓰지 않는다. `vector`·`string`이 메모리를 알아서 관리해주기 때문이다. 다만 **참조(`&`)의 동작**과 **연결 리스트/트리 문제에서의 포인터**는 알아야 하므로, 개념 위주로 정리한다.

---

## 포인터

### 주소와 역참조

> **포인터** : 다른 변수의 **메모리 주소**를 담는 변수. `&`로 주소를 얻고, `*`로 그 주소의 값에 접근(역참조)한다.

```cpp
int x = 5;
int* p = &x;        // p = x의 주소

cout << p;          // 주소값 (예: 0x7ffe...)
cout << *p;         // 5   (역참조 → x의 값)

*p = 10;            // 역참조로 값 수정
cout << x;          // 10  (x가 바뀜! p가 x를 가리키므로)
```

| 기호 | 의미 | 예시 |
|------|------|------|
| `int* p` | 포인터 선언 | p는 int의 주소를 담음 |
| `&x` | 주소 얻기(address-of) | x의 주소 |
| `*p` | 역참조(dereference) | p가 가리키는 값 |

### nullptr

> 아무것도 가리키지 않는 포인터. `nullptr`로 초기화한다. (옛 `NULL`보다 `nullptr` 권장)

```cpp
int* p = nullptr;        // 빈 포인터

if (p != nullptr) {      // 가리키는 게 있는지 확인 후 사용
    cout << *p;
}
```

> ⚠️ `nullptr`(또는 쓰레기 주소)를 역참조하면 **프로그램이 죽는다**(segfault). 역참조 전에 항상 유효한지 확인하라. **연결 리스트·트리 순회에서 `next`/`left`가 `nullptr`인지 검사하는 게 필수**다.

### 포인터로 연결 구조 다루기 (코테 활용)

> 연결 리스트·트리 문제는 노드를 포인터로 잇는다. `->`는 "포인터가 가리키는 객체의 멤버"에 접근한다(`(*p).member`의 축약).

```cpp
struct Node {
    int val;
    Node* next;   // 다음 노드를 가리키는 포인터
};

// 연결 리스트 순회
Node* cur = head;
while (cur != nullptr) {   // nullptr이면 끝
    cout << cur->val;      // (*cur).val 과 동일
    cur = cur->next;       // 다음으로 이동
}
```

> 💡 코테에선 연결 리스트도 `vector`·인덱스로 대체하는 경우가 많다. 하지만 트리 구조(`left`/`right` 포인터)는 포인터로 다루는 게 자연스럽다.

## 참조 (코테에서 더 중요)

### 참조 변수

> **참조(reference)** : 기존 변수의 **별명(alias)**. `&`를 타입에 붙여 선언하며, 한 번 묶이면 그 변수 그 자체처럼 동작한다.

```cpp
int x = 5;
int& ref = x;       // ref는 x의 별명

ref = 10;
cout << x;          // 10  (ref를 바꾸면 x가 바뀜)
```

> ⚠️ 참조는 **선언 시 반드시 초기화**해야 하고, 한 번 묶이면 **다른 변수로 바꿀 수 없다**(rebind 불가).

### 포인터 vs 참조

| | 포인터 (`int* p`) | 참조 (`int& r`) |
|--|-------------------|------------------|
| 초기화 | 나중에 가능 | 선언 시 필수 |
| 재지정 | 다른 대상 가리키기 가능 | 불가 (한 대상 고정) |
| null | 가능 (`nullptr`) | 불가 (항상 유효) |
| 문법 | `*p`로 역참조 | 변수처럼 바로 사용 |

> 💡 **코테에서 참조가 중요한 이유:** 함수에 큰 컨테이너를 넘길 때 `vector<int>& v`(수정) 또는 `const vector<int>& v`(읽기 전용)로 넘기면 **복사 없이** 원본을 다룬다. 값 복사는 시간 초과의 숨은 원인이다. (`03.cpp_functions`의 "참조 전달" 참고)

```cpp
// 범위 기반 for에서도 참조로 원본 수정
vector<int> v = {1, 2, 3};
for (int& x : v) x *= 2;   // {2, 4, 6}
```

## 메모리

### 스택 vs 힙

> 변수는 두 종류의 메모리 영역에 저장된다.

| 영역 | 특징 | 할당 방식 |
|------|------|-----------|
| 스택(stack) | 빠름, **크기 제한(1~8MB)**, 자동 해제 | 일반 지역 변수 |
| 힙(heap) | 큼, 느림, 수동 관리 | `new`로 직접 할당 |

```cpp
int a = 5;              // 스택: 함수 끝나면 자동 소멸
int* p = new int(5);    // 힙: 직접 delete 해야 소멸
```

> ⚠️ **코테 관점 — 큰 배열은 스택에 두지 마라.** `int arr[10000000]`을 함수 안에 두면 스택 한도를 넘겨 죽는다. **전역**으로 빼거나 `vector`(내부적으로 힙 사용)를 써라. (`03.cpp_functions`의 전역 배열 참고)

### 동적 할당 (new / delete)

> 실행 중에 힙에서 메모리를 직접 잡고(`new`) 직접 반납(`delete`)한다.

```cpp
int* p = new int(42);   // 힙에 int 하나 할당
cout << *p;             // 42
delete p;               // 반납 (필수!)

int* arr = new int[5];  // 배열 할당
delete[] arr;           // 배열은 delete[] 로 반납
```

> ⚠️ `new`한 건 반드시 `delete`. 배열은 `delete[]`. 짝을 안 맞추면 **메모리 누수**가 난다. 그래서 현대 C++·코테에선 raw `new`를 피하고 `vector`·스마트 포인터를 쓴다.

## 참고

### 스마트 포인터

> `new`/`delete`를 손으로 맞추는 건 실수가 잦다. **스마트 포인터**는 범위를 벗어나면 **자동으로 메모리를 반납**한다. (`#include <memory>`)

```cpp
#include <memory>
unique_ptr<int> p = make_unique<int>(5);  // C++14
cout << *p;     // 5
// delete 불필요 — p가 사라질 때 자동 반납
```

| 스마트 포인터 | 의미 |
|---------------|------|
| `unique_ptr` | 소유자 **하나** (복사 불가, 이동만) |
| `shared_ptr` | 여러 소유자 공유 (참조 카운트) |

> 💡 `make_unique`는 C++14부터 제공된다(`make_shared`는 C++11). 코테에선 거의 안 쓰지만, RAII 원리를 이해하는 예로 알아두면 된다.

### RAII — 왜 vector면 충분한가

> **RAII (Resource Acquisition Is Initialization)** : 자원을 객체가 쥐고, **객체가 사라질 때 소멸자가 자동으로 반납**하는 C++ 핵심 패턴.

```cpp
{
    vector<int> v(1000000);   // 내부적으로 힙에 메모리 할당
    // ... 사용 ...
}   // 블록 끝 → v 소멸 → 메모리 자동 반납
```

> 💡 **네가 쓰는 `vector`·`string`이 전부 RAII다.** 내부적으로 힙 메모리를 잡지만 범위를 벗어나면 알아서 반납한다. 그래서 코테에선 raw 포인터·`new`/`delete`를 쓸 일이 거의 없다 — 컨테이너가 다 해준다.

### const 참조로 복사 방지

> 함수에 큰 데이터를 **읽기 전용으로** 넘길 때 `const T&`를 쓴다. 복사 비용 없이 원본 수정도 막는다.

```cpp
void print(const vector<int>& v) {   // 복사 안 함, 수정 불가
    for (int x : v) cout << x;
}
```

> 💡 이게 코테에서 포인터·참조를 아는 실질적 이유다. 원리(주소를 넘긴다)를 이해하면 왜 `const T&`가 빠른지 납득된다.
