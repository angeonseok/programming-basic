# 🔷 C++ 기초 문법 — 포인터 · 참조 · 메모리

> 파이썬은 메모리 주소·할당을 전부 숨기고 GC(가비지 컬렉터)가 관리했다. C++은 **메모리를 직접 보고, 직접 다룬다.** 포인터는 C++을 C++답게 만드는 핵심 개념이다.
>
> 반복자(`it`), 참조(`&`), `this`, 문자열 리터럴, 다형성(`Animal* a = new Dog()`), `vector`의 내부 구현이 모두 포인터 위에 서 있다. 포인터를 이해하면 앞 문서들에서 "그냥 외웠던" 규칙들의 이유가 보인다.
>
> 💡 **코테 관점:** 실전 코드에선 raw 포인터·`new`/`delete`를 직접 쓸 일이 드물다(`vector`·`string`이 대신한다). 하지만 연결 리스트·트리 문제, 참조 전달, 반복자, 그리고 **런타임 에러의 원인**을 이해하려면 이 문서의 내용이 필요하다.

## 메모리와 주소 — 먼저 그림부터

> 메모리는 **번호가 붙은 거대한 바이트 배열**이다. 변수는 그 안의 칸 몇 개를 차지하고, 그 칸의 시작 번호가 **주소**다.

```text
 주소(예시)    메모리            변수
 ──────────   ─────────────    ─────────────────────────────
 0x1000       [      5      ]  ← int x          (4바이트)
 0x1004       [     ...     ]
 0x1008       [   0x1000    ]  ← int* p = &x    (8바이트, x의 주소를 값으로 가짐)
```

```cpp
int x = 5;
cout << &x << "\n";          // x의 주소 (예: 0x7ffe5c3c)
cout << sizeof(x) << "\n";   // 4  (x가 차지하는 바이트 수)
```

> 💡 **포인터 = 주소를 값으로 담는 변수.** 위 그림에서 `p`의 값은 `0x1000`이고, "`0x1000`번 칸에 가 보면 `int`가 있다"는 뜻이다. 포인터 변수 자체의 크기는 가리키는 타입과 관계없이 **64비트 환경에서 8바이트**다.

## 포인터 기초

### 선언 · 주소 · 역참조

> `&`로 주소를 얻고, `*`로 그 주소에 있는 값에 접근(역참조)한다.

```cpp
int x = 5;
int* p = &x;        // p = x의 주소

cout << p;          // 주소값 (예: 0x7ffe...)
cout << *p;         // 5   (역참조 → x의 값)

*p = 10;            // 역참조로 값 수정
cout << x;          // 10  (x가 바뀜! p가 x를 가리키므로)
```

| 기호 | 의미 | 예시 |
|------|------|------|
| `int* p` | 포인터 선언 | p는 int의 주소를 담음 |
| `&x` | 주소 얻기(address-of) | x의 주소 |
| `*p` | 역참조(dereference) | p가 가리키는 값 |

> 💡 같은 기호가 **위치에 따라 뜻이 다르다.** 타입 옆의 `*`는 "포인터 타입"(`int* p`), 식 안의 `*`는 "역참조"(`*p = 10`)다. 마찬가지로 타입 옆의 `&`는 "참조 타입"(`int& r`), 식 안의 `&`는 "주소 얻기"(`&x`)다.

### ⚠️ 선언 함정: `int* p, q;`

```cpp
int* p, q;     // p는 int*, q는 그냥 int!  (*는 바로 옆 변수 하나에만 붙는다)
int *a, *b;    // 둘 다 포인터로 만들려면 각각 *
```

> 💡 헷갈림을 피하려면 포인터는 **한 줄에 하나씩** 선언하자.

### 포인터에 타입이 있는 이유

> 주소는 그냥 숫자인데 왜 `int*`, `double*`처럼 타입을 나눌까? 역참조할 때 **몇 바이트를 어떤 형식으로 읽을지**, 그리고 `p + 1`이 **몇 바이트 뒤로 갈지**를 타입이 정하기 때문이다.

```cpp
int a[3] = {10, 20, 30};
int* p = a;
cout << *(p + 1);   // 20  → p + 1은 "1바이트 뒤"가 아니라 "int 하나(4바이트) 뒤"
```

### nullptr과 초기화 안 한 포인터

> 아무것도 가리키지 않는 포인터는 `nullptr`로 표시한다.

```cpp
int* p = nullptr;        // ✅ "아무것도 안 가리킴"을 명시
int* q;                  // ❌ 지역 변수라 쓰레기 주소 → 역참조하면 어디를 건드릴지 모름

if (p != nullptr) {      // 가리키는 게 있는지 확인 후 사용
    cout << *p;
}
```

> ⚠️ `nullptr`(또는 쓰레기 주소)를 역참조하면 **프로그램이 죽는다**(segfault). 포인터는 선언할 때 **유효한 주소나 `nullptr`로 반드시 초기화**하고, 역참조 전에 유효한지 확인하라. **연결 리스트·트리 순회에서 `next`/`left`가 `nullptr`인지 검사하는 게 필수**다.

> 💡 옛 코드의 `NULL`은 사실상 정수 `0`이라서, 함수 오버로딩에서 포인터 버전 대신 `int` 버전이 불리는 등 헷갈리는 일이 생긴다. C++11부터는 항상 `nullptr`를 쓴다.

## 포인터와 함수

### 주소를 넘기면 원본을 바꿀 수 있다

> 값으로 넘기면 함수는 **복사본**을 받는다. 주소를 넘기면 함수가 그 주소로 찾아가 **호출한 쪽의 변수**를 직접 바꿀 수 있다. 참조(`&`)는 이걸 더 편한 문법으로 감싼 것이다.

```cpp
void swapVal(int a, int b)   { int t = a; a = b; b = t; }      // ❌ 복사본만 바뀜
void swapPtr(int* a, int* b) { int t = *a; *a = *b; *b = t; }  // ✅ 주소로 원본 수정
void swapRef(int& a, int& b) { int t = a; a = b; b = t; }      // ✅ 참조로 원본 수정

int x = 1, y = 2;
swapVal(x, y);     // x=1, y=2 (그대로)
swapPtr(&x, &y);   // x=2, y=1 (호출할 때 & 로 주소를 넘김)
swapRef(x, y);     // x=1, y=2 (다시 바뀜. 호출 문법은 값 전달과 똑같다)
```

> 💡 C++에선 "원본 수정"이 목적이면 **참조**를 쓴다. 포인터 매개변수는 "**없을 수도 있음**(`nullptr` 허용)"을 표현하고 싶을 때나, C 라이브러리(`scanf("%d", &n)`)에서 만난다.

### 함수도 주소가 있다 (함수 포인터)

> 함수 이름은 그 함수의 주소로 바뀐다. 그래서 일반 함수를 `sort`의 비교 기준으로 넘길 수 있다.

```cpp
bool desc(int a, int b) { return a > b; }

sort(v.begin(), v.end(), desc);   // 함수 이름 = 함수 주소
bool (*cmp)(int, int) = desc;     // 함수 포인터 변수: "int 두 개를 받아 bool을 반환하는 함수의 주소"
cout << cmp(3, 1);                // 1 (true)
```

> 💡 함수 포인터 문법은 읽기 어렵다. 요즘은 람다(`03.cpp_functions`)나 `std::function`을 주로 쓴다.

## 배열과 포인터

> 배열 이름은 대부분의 식에서 **첫 원소의 주소**로 바뀐다(decay). 그래서 `arr[i]`는 사실 `*(arr + i)`의 축약이다.

```cpp
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr;              // arr == &arr[0]

cout << *(p + 2);          // 30  (arr[2]와 같음)
cout << p[2];              // 30  (포인터에도 [] 사용 가능)

for (int* q = arr; q != arr + 5; q++)   // 포인터로 순회
    cout << *q << " ";                  // 10 20 30 40 50

int* last = &arr[4];
cout << last - arr;        // 4  (포인터끼리 빼면 사이의 칸 수 = 인덱스)

sort(arr, arr + 5);        // 06의 이 코드가 동작하는 이유: [arr, arr+5) = 첫 원소 ~ 마지막 다음
```

> 💡 `it - v.begin()`으로 인덱스를 구하는 관용구(`06`)도 같은 원리다. `arr + 5`처럼 **마지막 다음 칸**을 가리키는 것까지는 허용되지만, 그 칸을 역참조(`*(arr + 5)`)하면 범위 초과다.

> ⚠️ 배열을 함수에 넘기면 **포인터로 바뀌어** 크기 정보가 사라진다. 크기가 필요하면 따로 넘기거나 `vector`를 쓰자.
> ```cpp
> void f(int arr[]) {          // 사실 int* arr 와 같다
>     cout << sizeof(arr);     // 8 (포인터 크기). 배열 전체 크기가 아님
> }
> ```

> ⚠️ C++은 배열 범위를 **검사하지 않는다.** `arr[5]`, `arr[-1]`도 컴파일되고, 실행하면 옆 메모리를 읽거나 덮어쓴다(정의되지 않은 동작). 다른 변수 값이 이상하게 바뀌거나 RE가 난다. (`10.cpp_exception`의 디버깅 옵션 참고)

### 문자열 리터럴과 `char*`

> `"hi"`는 `string`이 아니라, 끝에 **널 문자 `'\0'`**이 붙은 `const char` 배열(`{'h', 'i', '\0'}`)이다. 식에서 쓰이면 첫 글자의 주소(`const char*`)가 된다. C 스타일 문자열은 `'\0'`을 만날 때까지를 문자열로 본다.

```cpp
const char* s = "hi";      // s는 'h'의 주소
cout << s;                 // hi  (cout은 char*를 받으면 주소 대신 '\0'까지의 글자를 출력)
cout << sizeof("hi");      // 3   ('\0' 포함)
cout << strlen(s);         // 2   (<cstring>, '\0' 전까지 센다)

string t = s;              // const char* → string 변환 OK
const char* u = t.c_str(); // string → const char* (C 함수에 넘길 때)
```

> 💡 앞 문서들의 이상한 규칙이 전부 여기서 나온다.
> - `auto s = "hi";`가 `string`이 아니라 `const char*`인 이유 (`01`, `09`의 CTAD)
> - `"ab" + "cd"`가 컴파일 에러인 이유 → **포인터 + 포인터**는 정의되지 않은 연산이라서 (`04`)
> - `"abc" + 1`이 `"bc"`가 되는 이유 → 포인터를 한 칸 뒤로 옮긴 것

### const와 포인터

> `const`가 `*`의 **왼쪽**에 있으면 "가리키는 값"이, **오른쪽**에 있으면 "포인터 자체"가 고정된다.

| 선언 | 값(`*p`) 수정 | 다른 곳 가리키기(`p = ...`) |
|------|---------------|------------------------------|
| `const int* p` | ❌ | ✅ |
| `int* const p` | ✅ | ❌ |
| `const int* const p` | ❌ | ❌ |

```cpp
int x = 1, y = 2;
const int* p1 = &x;   // *p1 = 5; ❌   p1 = &y; ✅
int* const p2 = &x;   // *p2 = 5; ✅   p2 = &y; ❌
```

> 💡 **오른쪽에서 왼쪽으로** 읽으면 쉽다. `const int* p` → "p는 / 포인터(`*`) / const int를 가리키는". `int* const p` → "p는 / const인 / 포인터 / int를 가리키는".

### 포인터의 포인터

> 포인터도 변수라서 주소가 있다. 그 주소를 담으면 `int**`가 된다. `main(int argc, char** argv)`나 C 스타일 2차원 동적 배열에서 만난다.

```cpp
int x = 5;
int* p = &x;
int** pp = &p;      // p의 주소
cout << **pp;       // 5  (pp → p → x)
```

## 반복자는 포인터를 흉내 낸 것

> STL 반복자는 **포인터처럼 동작하도록** 만든 객체다. 그래서 문법이 똑같다. `vector`의 반복자는 실제로 내부 배열을 가리키는 포인터를 감싼 것이다.

| 포인터 | 반복자 | 의미 |
|--------|--------|------|
| `*p` | `*it` | 가리키는 값 |
| `p->x` | `it->first` | 가리키는 객체의 멤버 |
| `p++` | `++it` | 다음 원소로 |
| `arr + n` | `v.end()` | 마지막 **다음** |
| `q - p` | `it - v.begin()` | 사이 칸 수 (인덱스) |

```cpp
map<string, int> m = {{"a", 1}};
auto it = m.begin();
cout << it->first << " " << it->second;   // a 1   ( (*it).first 와 같음 )
```

> 💡 `05`의 **반복자 무효화**도 포인터로 이해하면 쉽다. `vector`가 커지면서 원소들이 새 메모리로 이사 가면, 옛 주소를 들고 있던 포인터·반복자·참조는 이제 **아무 의미 없는 주소**를 가리킨다.

## 연결 구조 — 연결 리스트 · 트리

> 노드끼리 포인터로 이어 붙인 자료구조. `->`는 "포인터가 가리키는 객체의 멤버"(`(*p).member`의 축약)다.

### 연결 리스트 (만들기 · 순회 · 해제)

```cpp
struct Node {
    int val;
    Node* next;
    Node(int v, Node* n = nullptr) : val(v), next(n) {}
};

// 만들기: 앞에 끼워 넣기 → 3 → 2 → 1
Node* head = nullptr;
for (int i = 1; i <= 3; i++)
    head = new Node(i, head);     // 새 노드가 기존 head를 가리키고, 새 노드가 head가 됨

// 순회
for (Node* cur = head; cur != nullptr; cur = cur->next)
    cout << cur->val << " ";      // 3 2 1

// 해제: 다음 노드 주소를 먼저 챙기고 지운다
while (head != nullptr) {
    Node* nxt = head->next;
    delete head;
    head = nxt;
}
```

> ⚠️ `delete head;` 다음에 `head->next`를 읽으면 이미 반납한 메모리를 읽는 것(댕글링)이다. **지우기 전에 다음 주소를 저장**하는 순서가 중요하다.

### 이진 트리 (재귀 순회)

아래 코드가 만드는 트리:

```text
    2
   / \
  1   3
```

```cpp
struct TreeNode {
    int val;
    TreeNode* left = nullptr;
    TreeNode* right = nullptr;
    TreeNode(int v) : val(v) {}
};

void inorder(TreeNode* node) {       // 중위 순회: 왼쪽 → 자신 → 오른쪽
    if (node == nullptr) return;     // 기저 조건: 빈 자리
    inorder(node->left);
    cout << node->val << " ";
    inorder(node->right);
}

TreeNode* root = new TreeNode(2);
root->left = new TreeNode(1);
root->right = new TreeNode(3);
inorder(root);   // 1 2 3
```

> 💡 코테 트리 문제는 노드 번호와 `vector<int> left(n), right(n)` 같은 **배열 인덱스**로 트리를 표현하는 경우가 더 많다. 포인터 트리는 LeetCode식 문제나 실무 코드에서 주로 만난다.

> 💡 위 트리는 `delete`로 해제하지 않았다. 해제하려면 후위 순회로 자식부터 지워야 한다. 이 번거로움을 없애는 게 아래의 **스마트 포인터**다.

## 참조

### 참조 변수

> **참조(reference)** : 기존 변수의 **별명(alias)**. `&`를 타입에 붙여 선언하며, 한 번 묶이면 그 변수 그 자체처럼 동작한다.

```cpp
int x = 5;
int& ref = x;       // ref는 x의 별명

ref = 10;
cout << x;          // 10  (ref를 바꾸면 x가 바뀜)
```

> ⚠️ 참조는 **선언 시 반드시 초기화**해야 하고, 한 번 묶이면 **다른 변수로 바꿀 수 없다**(rebind 불가).

> 💡 참조는 내부적으로는 주소를 들고 있지만, 문법상 변수 그 자체처럼 쓰게 해주는 장치다. "**절대 null이 아니고, 다른 대상으로 바뀌지 않는 포인터**"라고 생각하면 된다.

### 포인터 vs 참조

| | 포인터 (`int* p`) | 참조 (`int& r`) |
|--|-------------------|------------------|
| 초기화 | 나중에 가능 | 선언 시 필수 |
| 재지정 | 다른 대상 가리키기 가능 | 불가 (한 대상 고정) |
| null | 가능 (`nullptr`) | 불가 (항상 유효) |
| 문법 | `*p`로 역참조 | 변수처럼 바로 사용 |

| 상황 | 쓸 것 |
|------|-------|
| 함수에서 원본 수정 | `T&` |
| 큰 데이터 읽기 전용 전달 | `const T&` |
| 없을 수도 있는 대상 | `T*` (`nullptr` 가능) 또는 `optional` (`03`) |
| 가리키는 대상을 바꿔 가며 이동 (연결 리스트 순회) | `T*` |

> 💡 **코테에서 참조가 중요한 이유:** 함수에 큰 컨테이너를 넘길 때 `vector<int>& v`(수정) 또는 `const vector<int>& v`(읽기 전용)로 넘기면 **복사 없이** 원본을 다룬다. 값 복사는 시간 초과의 숨은 원인이다. (`03.cpp_functions`의 "참조 전달" 참고)

```cpp
void print(const vector<int>& v) {   // 복사 안 함, 수정 불가
    for (int x : v) cout << x;
}

vector<int> v = {1, 2, 3};
for (int& x : v) x *= 2;             // 범위 기반 for에서도 참조로 원본 수정 → {2, 4, 6}
```

### const 참조는 임시값도 받는다

```cpp
// int& r = 5;           // ❌ 일반 참조는 이름 있는 변수만 받는다
const int& r = 5;        // ✅ const 참조는 임시값(리터럴, 식의 결과)도 받는다

void print(const string& s);
print("hello");          // ✅ "hello"로 임시 string을 만들어 넘김

void edit(string& s);
// edit("hello");        // ❌ 컴파일 에러
```

> 💡 그래서 읽기 전용 매개변수는 `const T&`가 가장 범용적이다. 변수, 리터럴, 식의 결과를 모두 복사 없이 받는다.

### lvalue · rvalue (값의 종류)

> 식의 값은 크게 두 종류다. 이 구분이 참조와 **이동**(아래)의 규칙을 정한다.

| 종류 | 뜻 | 예 | `&`로 주소 얻기 |
|------|----|----|------------------|
| lvalue | 이름이 있고 계속 존재하는 값 | `x`, `v[0]`, `*p` | 가능 |
| rvalue | 식이 끝나면 사라지는 임시값 | `5`, `x + 1`, `string("a")`, 값으로 반환된 결과 | 불가 |

| 참조 | 받을 수 있는 것 |
|------|-----------------|
| `T&` | lvalue만 |
| `const T&` | lvalue, rvalue 모두 |
| `T&&` (rvalue 참조, C++11) | rvalue만 → "곧 사라질 값이니 내용물을 가져가도 된다" |

## 메모리 영역과 변수의 수명

> 변수는 **어디에 선언했느냐**에 따라 저장되는 영역과 **살아 있는 기간(수명)**이 달라진다.

| 영역 | 무엇이 | 수명 | 특징 |
|------|--------|------|------|
| 코드 | 컴파일된 함수 | 프로그램 전체 | 읽기 전용 |
| 정적(데이터) | 전역 변수, `static` 변수, 문자열 리터럴 | 프로그램 시작 ~ 끝 | **자동 0 초기화**, 큰 배열도 OK |
| 스택 | 지역 변수, 매개변수 | 블록(`{}`) 시작 ~ 끝 | 빠름, **크기 제한(1~8MB)**, 자동 해제 |
| 힙 | `new`로 할당한 것 | `delete`할 때까지 | 큼, 직접 관리 (또는 `vector`·스마트 포인터가 관리) |

```cpp
int g[1'000'000];               // 정적: 프로그램 내내 존재, 전부 0

void f() {
    int a = 5;                  // 스택: f가 끝나면 사라짐
    static int calls = 0;       // 정적: f가 끝나도 값 유지 (처음 한 번만 초기화)
    calls++;                    // f를 세 번 부르면 1, 2, 3
    int* p = new int(5);        // p(주소, 8바이트)는 스택에, *p(int)는 힙에
    delete p;                   // 힙 메모리는 직접 반납
}                               // 여기서 a, p 소멸 (calls는 유지)
```

> 💡 `03`에서 "큰 배열은 전역에 두라"고 한 이유가 이 표다. 전역은 정적 영역이라 스택 한도와 무관하고 자동으로 0이 된다. `int arr[10000000]`을 함수 안에 두면 스택 한도를 넘겨 죽는다. **전역**으로 빼거나 `vector`(내부적으로 힙 사용)를 써라.

### 스택과 함수 호출

> 함수를 호출할 때마다 스택에 그 함수의 지역 변수 묶음(**스택 프레임**)이 쌓이고, 함수가 끝나면 치워진다.

```text
main 호출   →  [main]
f(3) 호출   →  [main][f(3)]
f(2) 호출   →  [main][f(3)][f(2)]
f(2) 끝     →  [main][f(3)]          ← f(2)의 지역 변수는 이제 없음
```

> 💡 재귀가 깊어지면 프레임이 계속 쌓여 스택 한도를 넘는다. 이것이 **스택 오버플로**다(`03`의 재귀 참고).

> ⚠️ 그래서 **지역 변수의 주소나 참조를 반환하면 안 된다.** 함수가 끝나는 순간 그 프레임이 치워져서, 반환된 주소는 이미 사라진 변수를 가리킨다(`03`의 "참조 반환 주의").
> ```cpp
> int* bad() { int x = 5; return &x; }   // ❌ 댕글링 포인터
> ```

### 동적 할당 (new / delete)

> 실행 중에 힙에서 메모리를 직접 잡고(`new`) 직접 반납(`delete`)한다.

```cpp
int* p = new int(42);   // 힙에 int 하나 할당
cout << *p;             // 42
delete p;               // 반납 (필수!)

int* arr = new int[5];  // 배열 할당
delete[] arr;           // 배열은 delete[] 로 반납

string* sp = new string("hello");   // 객체도 가능: 생성자가 불림
cout << sp->size();                  // 5
delete sp;                           // 소멸자가 불리고 메모리 반납
```

> ⚠️ `new`한 건 반드시 `delete`. 배열은 `delete[]`. 짝을 안 맞추면 **메모리 누수**나 정의되지 않은 동작이 생긴다. 그래서 현대 C++에선 raw `new`를 피하고 `vector`·스마트 포인터를 쓴다.

### 흔한 메모리 버그

| 버그 | 예시 | 결과 |
|------|------|------|
| 초기화 안 한 포인터 | `int* p; *p = 1;` | 아무 곳이나 덮어씀 → RE 또는 이상한 값 |
| 널 포인터 역참조 | `Node* p = nullptr; p->val;` | 즉시 RE (segfault) |
| 댕글링 포인터 | `delete p; *p = 1;` / 지역 변수 주소 반환 | 이미 반납한 메모리 사용 → 예측 불가 |
| 이중 해제 | `delete p; delete p;` | RE |
| `new[]`/`delete` 짝 불일치 | `int* a = new int[5]; delete a;` | 정의되지 않은 동작 |
| 메모리 누수 | `new` 후 `delete` 안 함 | 당장은 멀쩡, 오래 돌면 메모리 부족 |
| 범위 밖 접근 | `arr[n]`, `arr[-1]` | 옆 변수 오염 또는 RE |

> 💡 `delete p;` 뒤에 `p = nullptr;`를 해두면 이중 해제·댕글링을 조금 막을 수 있다(`delete nullptr`는 아무 일도 하지 않는다). 하지만 근본 해결은 **raw `new`/`delete`를 쓰지 않는 것**, 즉 `vector`와 스마트 포인터다. 이런 버그는 `10.cpp_exception`의 디버깅 옵션(`-fsanitize=address`)이 위치를 정확히 알려준다.

## 스마트 포인터 — 소유권을 타입으로 표현

> `new`/`delete`를 손으로 맞추는 건 실수가 잦다. **스마트 포인터**는 포인터를 감싼 객체로, 자신이 사라질 때 **가리키던 메모리를 자동으로 `delete`**한다. (`#include <memory>`)

### unique_ptr — 혼자 소유

```cpp
#include <memory>
{
    unique_ptr<int> p = make_unique<int>(5);   // C++14
    cout << *p;                                 // 5  (일반 포인터처럼 *, -> 사용)

    // unique_ptr<int> q = p;                   // ❌ 복사 불가 (소유자는 하나뿐)
    unique_ptr<int> q = std::move(p);           // ✅ 소유권 이전 → 이제 p는 비어 있음(nullptr)
    if (!p) cout << "p는 비었음\n";
}   // 블록 끝 → q가 사라지며 자동으로 delete
```

트리를 `unique_ptr`로 만들면 해제 코드가 필요 없다.

```cpp
struct TreeNode {
    int val;
    unique_ptr<TreeNode> left, right;   // 자식을 "소유"
    TreeNode(int v) : val(v) {}
};

void inorder(const TreeNode* node) {     // 읽기만 하므로 소유권 없이 raw 포인터로 받음
    if (node == nullptr) return;
    inorder(node->left.get());           // .get() = 안에 든 raw 포인터
    cout << node->val << " ";
    inorder(node->right.get());
}

auto root = make_unique<TreeNode>(2);
root->left = make_unique<TreeNode>(1);
root->right = make_unique<TreeNode>(3);
inorder(root.get());   // 1 2 3
// delete 불필요: root가 사라지면 자식들도 연쇄적으로 자동 해제
```

> 💡 "**`unique_ptr` = 소유, raw 포인터·참조 = 빌려 보기**"로 역할을 나누는 게 현대 C++의 관례다. 함수가 대상을 읽기만 한다면 소유권(`unique_ptr`)을 넘기지 말고 `.get()`이나 참조로 넘긴다.

### shared_ptr — 여럿이 공유

```cpp
shared_ptr<int> a = make_shared<int>(10);
shared_ptr<int> b = a;            // 복사 가능: 같은 대상을 함께 소유
cout << a.use_count();            // 2  (소유자 수)
b.reset();                        // b가 소유를 포기 → 1
// 마지막 소유자가 사라질 때 delete
```

> ⚠️ 두 객체가 서로를 `shared_ptr`로 가리키면(**순환 참조**) 소유자 수가 0이 되지 않아 영원히 해제되지 않는다. 한쪽을 `weak_ptr`(소유하지 않고 지켜보기만 하는 포인터)로 바꿔 순환을 끊는다.

| 스마트 포인터 | 소유 | 복사 | 언제 |
|---------------|------|------|------|
| `unique_ptr` | 하나 | ❌ (이동만) | **기본 선택.** 동적 객체가 필요하면 먼저 이것 |
| `shared_ptr` | 여럿 (참조 카운트) | ✅ | 소유자가 정말 여럿일 때 |
| `weak_ptr` | 소유 안 함 | ✅ | `shared_ptr`의 순환 끊기 |

> 💡 `make_unique`는 C++14, `make_shared`는 C++11부터 있다. `new`를 직접 쓰지 말고 이 함수들로 만들자.

## RAII — 왜 vector면 충분한가

> **RAII (Resource Acquisition Is Initialization)** : 자원을 객체가 쥐고, **객체가 사라질 때 소멸자가 자동으로 반납**하는 C++의 핵심 패턴. 스마트 포인터도 RAII다.

```cpp
{
    vector<int> v(1000000);   // 내부적으로 힙에 메모리 할당
    // ... 사용 ...
}   // 블록 끝 → v 소멸 → 메모리 자동 반납
```

> 💡 **네가 쓰는 `vector`·`string`이 전부 RAII다.** 내부적으로 힙 메모리를 잡지만 범위를 벗어나면 알아서 반납한다. 그래서 코테에선 raw 포인터·`new`/`delete`를 쓸 일이 거의 없다. 컨테이너가 다 해준다.

## 이동 (move) — 복사 대신 넘겨주기

> C++11부터 객체를 **복사하지 않고 내부 자원(힙 메모리)만 넘겨주는** "이동"이 생겼다. `std::move(x)`는 "x는 이제 안 쓸 테니 내용물을 가져가도 된다"는 표시다. (`#include <utility>`)

```cpp
vector<int> a(1'000'000, 1);
vector<int> b = a;              // 복사: 원소 100만 개를 새로 복사 (O(n))
vector<int> c = std::move(a);   // 이동: a의 메모리를 c가 넘겨받음 (O(1))

vector<string> names;
string s = "아주 긴 문자열...";
names.push_back(std::move(s));  // s를 복사하지 않고 벡터 안으로 이동
```

> 💡 `std::move` 자체는 아무것도 옮기지 않는다. `x`를 **rvalue(`T&&`)로 바꿔 주는 캐스팅**일 뿐이다. 그 rvalue를 받은 이동 생성자가 내부 포인터만 넘겨받는 방식으로 내용물을 가져간다. `vector`의 이동이 O(1)인 이유는 원소가 아니라 **힙을 가리키는 포인터 하나만** 옮기기 때문이다.

> ⚠️ 이동한 뒤의 원본(`a`, `s`)은 "유효하지만 내용은 정해지지 않은" 상태다. 실제로는 보통 비어 있지만 그렇다고 가정하지 말고, **새 값을 대입하기 전엔 쓰지 마라.**

> 💡 함수가 지역 변수를 반환할 때는 `return std::move(v);`라고 쓰지 말고 그냥 `return v;`라고 써라. 컴파일러가 알아서 복사 생략·이동을 해주며, `std::move`를 붙이면 오히려 복사 생략을 방해한다(`03.cpp_functions` 참고).

## 정리 — 무엇을 쓸까

| 하고 싶은 것 | 쓸 것 |
|--------------|-------|
| 값 하나 저장 | 그냥 변수 (`int x`) |
| 함수에서 원본 수정 | 참조 `T&` |
| 큰 데이터를 읽기 전용으로 전달 | `const T&` |
| 크기가 바뀌는 배열 | `vector` |
| 동적으로 만든 객체를 혼자 소유 | `unique_ptr` |
| 여럿이 함께 소유 | `shared_ptr` |
| 소유하지 않고 가리키기 (없을 수도 있음) | raw 포인터 `T*` |
| 직접 `new` / `delete` | 거의 쓰지 않는다 |
