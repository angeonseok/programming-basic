# 🔷 C++ 기초 문법 — 프로그램 구조 (컴파일 · 헤더 · 네임스페이스)

> 파이썬은 `python a.py` 한 번이면 실행되고, `import`가 다른 파일을 알아서 찾아왔다. C++은 소스 코드가 **전처리 → 컴파일 → 링크**를 거쳐 실행 파일이 되고, 여러 파일로 나눌 때는 **헤더(`.h`)와 소스(`.cpp`)**를 직접 나눠야 한다.
>
> 💡 **코테 관점:** 코테는 파일 하나라서 헤더 분리를 할 일은 없다. 하지만 **에러 메시지가 어느 단계에서 났는지** 읽는 법, `using namespace std;`가 일으키는 **이름 충돌**, 매크로와 **로컬 전용 디버그 출력**은 코테에서도 바로 쓰인다.

---

## 소스 코드가 실행 파일이 되기까지

```text
main.cpp ─▶ [전처리] ─▶ [컴파일] ─▶ main.o ─┐
util.cpp ─▶ [전처리] ─▶ [컴파일] ─▶ util.o ─┼─▶ [링크] ─▶ app.exe
                                표준 라이브러리 ─┘
```

| 단계 | 하는 일 | 이 단계에서 나는 에러 예 |
|------|---------|--------------------------|
| 전처리 | `#include` 내용 붙여넣기, `#define` 치환 | `fatal error: util.h: No such file or directory` |
| 컴파일 | `.cpp` **하나씩 따로** 기계어(`.o`)로 번역 | 문법 오류, 타입 불일치, `'x' was not declared` |
| 링크 | `.o` 파일들과 라이브러리를 연결 | `undefined reference to 'add(int, int)'`, `multiple definition of 'sq(int)'` |

> 💡 **핵심은 "컴파일러는 `.cpp` 파일을 하나씩 따로 본다"는 것.** 다른 파일에 있는 함수는 **선언**만 보고 "어딘가 있겠지" 하고 넘어간다. 그 함수를 실제로 찾아 연결하는 건 링커다. 그래서 "선언은 있는데 정의가 없다"는 실수는 컴파일 에러가 아니라 **링크 에러**로 나온다.

> 💡 `g++ sol.cpp -o sol` 한 줄이 위 세 단계를 전부 해준다. 단계를 나눠 보고 싶으면 `g++ -E`(전처리 결과만), `g++ -c`(`.o`까지만)를 써 보자.

## 전처리기 (`#`으로 시작하는 줄)

> 전처리기는 컴파일 전에 **소스 코드를 텍스트로 편집**한다. C++ 문법을 이해하지 못하고 글자만 바꾼다.

### #include

> 지정한 파일의 내용을 **그 자리에 그대로 복사해 붙여넣는다.**

```cpp
#include <vector>       // < > : 표준·시스템 헤더 위치에서 찾는다
#include "util.h"       // " " : 현재 파일이 있는 폴더부터 찾는다 (내가 만든 헤더)
```

### #define 매크로와 그 함정

```cpp
#define MAX 100          // 이후 등장하는 MAX를 전부 100으로 치환
#define SQ(x) x * x      // 함수처럼 보이지만 그냥 글자 치환

SQ(1 + 2)                // 9가 아니라 5!  →  1 + 2 * 1 + 2 로 치환되기 때문
```

> ⚠️ 매크로는 타입도, 스코프(유효 범위)도 없고 괄호도 알아서 쳐 주지 않는다. C++에선 각각 더 안전한 대체제가 있다.
>
> | 매크로로 하던 것 | C++ 대체 |
> |------------------|----------|
> | `#define MAX 100` | `constexpr int MAX = 100;` ([02. 자료형 · 연산자](02.cpp_types_operators.md)) |
> | `#define ll long long` | `using ll = long long;` ([02. 자료형 · 연산자](02.cpp_types_operators.md)) |
> | `#define SQ(x) ((x) * (x))` | `inline int sq(int x) { return x * x; }` 또는 템플릿 ([12. 템플릿](12.cpp_template.md)) |

### 조건부 컴파일 — 로컬에서만 디버그 출력 (코테 실전)

> `#ifdef 이름`은 "그 이름이 정의돼 있을 때만" 코드를 남긴다. 컴파일 옵션 `-D이름`으로 정의할 수 있어서, **내 PC에서만 켜지는 디버그 출력**을 만들 수 있다.

```cpp
#ifdef LOCAL
#define debug(x) cerr << #x << " = " << (x) << "\n"   // #x : 인자를 글자 그대로 문자열로
#else
#define debug(x)                                       // 제출할 땐 아무것도 아닌 코드로 사라짐
#endif

int main() {
    int n = 7;
    debug(n * 2);   // 로컬: "n * 2 = 14" 출력 / 제출: 아무것도 안 함
}
```

```bash
g++ -std=c++17 -DLOCAL sol.cpp -o sol   # 로컬 테스트: LOCAL 정의 → debug 켜짐
```

> 💡 제출 전에 디버그 출력을 지우는 걸 깜빡해서 틀리는 일이 사라진다. `cerr`은 표준 에러로 출력돼서 `cout`의 답과 섞이지도 않는다.

## 선언과 정의

> **선언**은 "이런 이름이 있다"고 알려주는 것, **정의**는 그 실체(함수 본문, 변수의 메모리)를 만드는 것이다. 선언은 여러 번 해도 되지만, **정의는 프로그램 전체에서 딱 한 번**이어야 한다(ODR, One Definition Rule).

```cpp
int add(int a, int b);                    // 함수 선언 (본문 없음)
int add(int a, int b) { return a + b; }   // 함수 정의

extern int total;                         // 변수 선언 ("다른 파일에 정의돼 있음")
int total = 0;                            // 변수 정의 (메모리 확보)

struct Node;                              // 타입 선언 (전방 선언) — 포인터로만 쓸 수 있음
struct Node { int val; Node* next; };     // 타입 정의
```

> 💡 [04. 함수](04.cpp_functions.md)의 "선언과 정의 분리(프로토타입)"가 같은 개념이다. 파일 하나 안에서는 "호출보다 위에 선언이 있어야 한다"는 규칙으로, 여러 파일에서는 "**헤더에 선언, `.cpp`에 정의**"라는 규칙으로 나타난다.

## 헤더와 소스 분리 (여러 파일 프로그램)

### 기본 구조

> 다른 파일에서 쓸 함수의 **선언은 헤더(`.h`)에**, **정의는 소스(`.cpp`)에** 둔다. 쓰는 쪽은 헤더만 `#include`한다.

**math_utils.h** — 선언 (무엇이 있는지)
```cpp
#pragma once                 // 이 헤더가 여러 번 include돼도 한 번만 처리

int add(int a, int b);
```

**math_utils.cpp** — 정의 (어떻게 동작하는지)
```cpp
#include "math_utils.h"

int add(int a, int b) { return a + b; }
```

**main.cpp** — 사용
```cpp
#include <iostream>
#include "math_utils.h"

int main() {
    std::cout << add(2, 3) << "\n";   // 5
}
```

```bash
g++ -std=c++17 main.cpp math_utils.cpp -o app   # .cpp를 전부 함께 넘긴다
```

> ⚠️ `math_utils.cpp`를 빼고 `g++ main.cpp`만 하면 **링크 에러** `undefined reference to 'add(int, int)'`가 난다. `main.cpp`는 헤더의 선언 덕분에 컴파일은 되지만, `add`의 정의가 담긴 파일이 링크에 없기 때문이다.

### include guard — 중복 포함 막기

> 헤더 A와 B가 둘 다 `util.h`를 포함하고 `main.cpp`가 A와 B를 포함하면, `util.h`가 **두 번 붙여넣어져** 같은 정의가 중복된다. 이를 막는 장치가 include guard다.

```cpp
// 방법 1: 표준 방식
#ifndef MATH_UTILS_H         // 아직 정의 안 됐으면
#define MATH_UTILS_H         // 정의하고 아래 내용을 포함
int add(int a, int b);
#endif                       // 두 번째 포함 때는 MATH_UTILS_H가 이미 있어서 통째로 건너뜀

// 방법 2: 한 줄 (표준은 아니지만 모든 주요 컴파일러가 지원)
#pragma once
```

> 💡 **모든 헤더 맨 위에** 둘 중 하나를 넣는 습관을 들이자.

### ⚠️ 헤더에 정의를 넣으면 생기는 일

> include guard는 **한 `.cpp` 안에서의** 중복만 막는다. 헤더에 일반 함수의 **정의**를 넣고 두 `.cpp`가 그 헤더를 포함하면, 정의가 두 `.o`에 하나씩 생겨 링크 에러 `multiple definition of 'sq(int)'`가 난다.

```cpp
// util.h
int sq(int x) { return x * x; }            // ❌ 두 .cpp에서 include하면 multiple definition

inline int sq2(int x) { return x * x; }    // ✅ inline: 여러 파일에 있어도 하나로 취급
inline int counter = 0;                    // ✅ C++17 inline 변수 (08의 inline static과 같은 원리)
constexpr int MAXN = 100'001;              // ✅ constexpr 상수는 파일마다 따로 있어도 OK
```

> 💡 클래스 **안에서** 정의한 멤버 함수는 자동으로 `inline`이라 헤더에 둬도 된다. **템플릿도 헤더에 정의**한다. 컴파일러가 `T`마다 코드를 만들려면 각 `.cpp`에서 본문 전체가 보여야 하기 때문이다([12. 템플릿](12.cpp_template.md)).

| 헤더 (`.h`)에 | 소스 (`.cpp`)에 |
|---------------|-----------------|
| 함수 선언 | 함수 정의 |
| 클래스·구조체 정의 | 클래스 밖에서 정의한 멤버 함수 |
| 템플릿 전체 | 전역 변수 정의 (`int total = 0;`) |
| `inline` 함수·변수, `constexpr` 상수 | 그 파일에서만 쓰는 도우미 함수 |

## 네임스페이스

### 왜 필요한가

> 여러 라이브러리에 같은 이름(`count`, `sort`, `Point` ...)이 있으면 충돌한다. **네임스페이스**는 이름에 "성(姓)"을 붙여 구분한다. 표준 라이브러리의 모든 이름은 `std`라는 네임스페이스 안에 있다(`std::vector`, `std::sort`).

```cpp
namespace geo {
    struct Point { int x, y; };
    int dist2(Point a, Point b) {
        return (a.x - b.x) * (a.x - b.x) + (a.y - b.y) * (a.y - b.y);
    }
}

geo::Point a{0, 0}, b{3, 4};      // :: (범위 지정 연산자)로 접근
cout << geo::dist2(a, b);         // 25

namespace geo::detail { }         // C++17: 중첩 네임스페이스 축약
                                  // (= namespace geo { namespace detail { } })
```

### using 선언 vs using 지시어

```cpp
using std::cout;            // using 선언: cout 하나만 가져온다 (권장)
using std::vector;

using namespace std;        // using 지시어: std의 모든 이름을 가져온다
```

> 💡 `using namespace std;`는 파일 하나짜리 코테 코드에선 편해서 관례처럼 쓴다. 실무·여러 파일 코드에선 `std::`를 붙이거나 필요한 이름만 `using std::cout;`으로 가져온다.

> ⚠️ **헤더 파일에는 절대 `using namespace std;`를 쓰지 마라.** 그 헤더를 include하는 **모든 파일**에 std의 이름이 강제로 풀려서, 쓰는 사람이 피할 방법이 없다.

### ⚠️ 코테 단골: 전역 변수 이름 충돌

> `#include <bits/stdc++.h>`와 `using namespace std;`를 함께 쓰면 표준 라이브러리의 이름 수천 개가 전역에 풀린다. **전역 변수** 이름이 그중 하나와 겹치면 `reference to 'count' is ambiguous` 같은 컴파일 에러가 난다.

```cpp
#include <bits/stdc++.h>
using namespace std;

int count = 0;              // 전역 변수
int main() {
    count++;                // ❌ 에러: std::count(06의 함수)와 모호
}
```

실제로 충돌하는 흔한 이름들 (전역 변수로 쓰면 에러):

| 충돌하는 이름 | std에 있는 것 |
|---------------|---------------|
| `count`, `max`, `distance`, `next`, `prev` | 알고리즘·반복자 함수 |
| `left`, `right` | 출력 정렬 조작자 (`cout << left`) |
| `data`, `size` | 컨테이너 접근 함수 (C++17) |
| `list`, `array`, `hash`, `less`, `plus`, `rank` | 컨테이너·함수 객체·타입 특성 |

> 💡 해결법: ① 이름을 바꾼다(`cnt`, `dist`, `L`, `R`) ← 가장 간단 ② `::count`처럼 **전역 범위**를 명시한다 ③ `using namespace std;`를 쓰지 않는다. **지역 변수**는 바깥 이름을 가리기 때문에 `main` 안의 `int count = 0;`은 문제없다.

### 전역 범위 `::`

```cpp
int x = 1;              // 전역

int main() {
    int x = 2;          // 지역 x가 전역 x를 가린다(shadowing)
    cout << x;          // 2
    cout << ::x;        // 1  (앞에 아무것도 없는 :: = 전역 범위)
}
```

### 익명 네임스페이스 — 이 파일 전용 이름

> 이름 없는 `namespace { }` 안의 함수·변수는 **그 `.cpp` 파일 안에서만** 보인다. 다른 파일에 같은 이름이 있어도 링크 에러(multiple definition)가 나지 않는다. (옛 방식: 함수 앞에 `static`)

```cpp
// util.cpp
namespace {
    int helper(int x) { return x * 2; }   // util.cpp 밖에서는 안 보임
}

int publicFunc(int x) { return helper(x) + 1; }   // 헤더에 선언해서 공개하는 함수
```
