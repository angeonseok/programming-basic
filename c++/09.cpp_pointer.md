# 🔷 C++ 기초 문법 — 포인터 (메모리 · 주소 · 배열 · 연결 구조)

> 파이썬은 메모리 주소·할당을 전부 숨기고 GC(가비지 컬렉터)가 관리했다. C++은 **메모리를 직접 보고, 직접 다룬다.** 포인터는 C++을 C++답게 만드는 핵심 개념이다.
>
> 반복자(`it`), 참조(`&`), `this`, 문자열 리터럴, 다형성(`Animal* a = new Dog()`), `vector`의 내부 구현이 모두 포인터 위에 서 있다. 포인터를 이해하면 앞 문서들에서 "그냥 외웠던" 규칙들의 이유가 보인다.
>
> 💡 **코테 관점:** 실전 코드에선 raw 포인터·`new`/`delete`를 직접 쓸 일이 드물다(`vector`·`string`이 대신한다). 하지만 연결 리스트·트리 문제, 참조 전달, 반복자, 그리고 **런타임 에러의 원인**을 이해하려면 이 문서의 내용이 필요하다.

## 메모리와 주소 — 먼저 그림부터

> 메모리는 **번호가 붙은 거대한 바이트 배열**이다. 변수는 그 안의 칸 몇 개를 차지하고, 그 칸의 시작 번호가 **주소**다.

```text
 주소(예시)    메모리            변수
 ──────────   ─────────────    ─────────────────────────────
 0x1000       [      5      ]  ← int x          (4바이트)
 0x1004       [     ...     ]
 0x1008       [   0x1000    ]  ← int* p = &x    (8바이트, x의 주소를 값으로 가짐)
```

```cpp
int x = 5;
cout << &x << "\n";          // x의 주소 (예: 0x7ffe5c3c)
cout << sizeof(x) << "\n";   // 4  (x가 차지하는 바이트 수)
```

> 💡 **포인터 = 주소를 값으로 담는 변수.** 위 그림에서 `p`의 값은 `0x1000`이고, "`0x1000`번 칸에 가 보면 `int`가 있다"는 뜻이다. 포인터 변수 자체의 크기는 가리키는 타입과 관계없이 **64비트 환경에서 8바이트**다.

## 포인터 기초

### 선언 · 주소 · 역참조

> `&`로 주소를 얻고, `*`로 그 주소에 있는 값에 접근(역참조)한다.

```cpp
int x = 5;
int* p = &x;        // p = x의 주소

cout << p;          // 주소값 (예: 0x7ffe...)
cout << *p;         // 5   (역참조 → x의 값)

*p = 10;            // 역참조로 값 수정
cout << x;          // 10  (x가 바뀜! p가 x를 가리키므로)
```

| 기호 | 의미 | 예시 |
|------|------|------|
| `int* p` | 포인터 선언 | p는 int의 주소를 담음 |
| `&x` | 주소 얻기(address-of) | x의 주소 |
| `*p` | 역참조(dereference) | p가 가리키는 값 |

> 💡 같은 기호가 **위치에 따라 뜻이 다르다.** 타입 옆의 `*`는 "포인터 타입"(`int* p`), 식 안의 `*`는 "역참조"(`*p = 10`)다. 마찬가지로 타입 옆의 `&`는 "참조 타입"(`int& r`), 식 안의 `&`는 "주소 얻기"(`&x`)다.

### ⚠️ 선언 함정: `int* p, q;`

```cpp
int* p, q;     // p는 int*, q는 그냥 int!  (*는 바로 옆 변수 하나에만 붙는다)
int *a, *b;    // 둘 다 포인터로 만들려면 각각 *
```

> 💡 헷갈림을 피하려면 포인터는 **한 줄에 하나씩** 선언하자.

### 포인터에 타입이 있는 이유

> 주소는 그냥 숫자인데 왜 `int*`, `double*`처럼 타입을 나눌까? 역참조할 때 **몇 바이트를 어떤 형식으로 읽을지**, 그리고 `p + 1`이 **몇 바이트 뒤로 갈지**를 타입이 정하기 때문이다.

```cpp
int a[3] = {10, 20, 30};
int* p = a;
cout << *(p + 1);   // 20  → p + 1은 "1바이트 뒤"가 아니라 "int 하나(4바이트) 뒤"
```

### nullptr과 초기화 안 한 포인터

> 아무것도 가리키지 않는 포인터는 `nullptr`로 표시한다.

```cpp
int* p = nullptr;        // ✅ "아무것도 안 가리킴"을 명시
int* q;                  // ❌ 지역 변수라 쓰레기 주소 → 역참조하면 어디를 건드릴지 모름

if (p != nullptr) {      // 가리키는 게 있는지 확인 후 사용
    cout << *p;
}
```

> ⚠️ `nullptr`(또는 쓰레기 주소)를 역참조하면 **프로그램이 죽는다**(segfault). 포인터는 선언할 때 **유효한 주소나 `nullptr`로 반드시 초기화**하고, 역참조 전에 유효한지 확인하라. **연결 리스트·트리 순회에서 `next`/`left`가 `nullptr`인지 검사하는 게 필수**다.

> 💡 옛 코드의 `NULL`은 사실상 정수 `0`이라서, 함수 오버로딩에서 포인터 버전 대신 `int` 버전이 불리는 등 헷갈리는 일이 생긴다. C++11부터는 항상 `nullptr`를 쓴다.

## 포인터와 함수

### 주소를 넘기면 원본을 바꿀 수 있다

> 값으로 넘기면 함수는 **복사본**을 받는다. 주소를 넘기면 함수가 그 주소로 찾아가 **호출한 쪽의 변수**를 직접 바꿀 수 있다. 참조(`&`)는 이걸 더 편한 문법으로 감싼 것이다.

```cpp
void swapVal(int a, int b)   { int t = a; a = b; b = t; }      // ❌ 복사본만 바뀜
void swapPtr(int* a, int* b) { int t = *a; *a = *b; *b = t; }  // ✅ 주소로 원본 수정
void swapRef(int& a, int& b) { int t = a; a = b; b = t; }      // ✅ 참조로 원본 수정

int x = 1, y = 2;
swapVal(x, y);     // x=1, y=2 (그대로)
swapPtr(&x, &y);   // x=2, y=1 (호출할 때 & 로 주소를 넘김)
swapRef(x, y);     // x=1, y=2 (다시 바뀜. 호출 문법은 값 전달과 똑같다)
```

> 💡 C++에선 "원본 수정"이 목적이면 **참조**를 쓴다. 포인터 매개변수는 "**없을 수도 있음**(`nullptr` 허용)"을 표현하고 싶을 때나, C 라이브러리(`scanf("%d", &n)`)에서 만난다.

### 함수도 주소가 있다 (함수 포인터)

> 함수 이름은 그 함수의 주소로 바뀐다. 그래서 일반 함수를 `sort`의 비교 기준으로 넘길 수 있다.

```cpp
bool desc(int a, int b) { return a > b; }

sort(v.begin(), v.end(), desc);   // 함수 이름 = 함수 주소
bool (*cmp)(int, int) = desc;     // 함수 포인터 변수: "int 두 개를 받아 bool을 반환하는 함수의 주소"
cout << cmp(3, 1);                // 1 (true)
```

> 💡 함수 포인터 문법은 읽기 어렵다. 요즘은 람다([04. 함수](04.cpp_functions.md))나 `std::function`을 주로 쓴다.

## 배열과 포인터

> 배열 이름은 대부분의 식에서 **첫 원소의 주소**로 바뀐다(decay). 그래서 `arr[i]`는 사실 `*(arr + i)`의 축약이다.

```cpp
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr;              // arr == &arr[0]

cout << *(p + 2);          // 30  (arr[2]와 같음)
cout << p[2];              // 30  (포인터에도 [] 사용 가능)

for (int* q = arr; q != arr + 5; q++)   // 포인터로 순회
    cout << *q << " ";                  // 10 20 30 40 50

int* last = &arr[4];
cout << last - arr;        // 4  (포인터끼리 빼면 사이의 칸 수 = 인덱스)

sort(arr, arr + 5);        // 06의 이 코드가 동작하는 이유: [arr, arr+5) = 첫 원소 ~ 마지막 다음
```

> 💡 `it - v.begin()`으로 인덱스를 구하는 관용구([08. 알고리즘](08.cpp_algorithm.md))도 같은 원리다. `arr + 5`처럼 **마지막 다음 칸**을 가리키는 것까지는 허용되지만, 그 칸을 역참조(`*(arr + 5)`)하면 범위 초과다.

> ⚠️ 배열을 함수에 넘기면 **포인터로 바뀌어** 크기 정보가 사라진다. 크기가 필요하면 따로 넘기거나 `vector`를 쓰자.
> ```cpp
> void f(int arr[]) {          // 사실 int* arr 와 같다
>     cout << sizeof(arr);     // 8 (포인터 크기). 배열 전체 크기가 아님
> }
> ```

> ⚠️ C++은 배열 범위를 **검사하지 않는다.** `arr[5]`, `arr[-1]`도 컴파일되고, 실행하면 옆 메모리를 읽거나 덮어쓴다(정의되지 않은 동작). 다른 변수 값이 이상하게 바뀌거나 RE가 난다. ([13. 예외 처리](13.cpp_exception.md)의 디버깅 옵션 참고)

### 문자열 리터럴과 `char*`

> `"hi"`는 `string`이 아니라, 끝에 **널 문자 `'\0'`**이 붙은 `const char` 배열(`{'h', 'i', '\0'}`)이다. 식에서 쓰이면 첫 글자의 주소(`const char*`)가 된다. C 스타일 문자열은 `'\0'`을 만날 때까지를 문자열로 본다.

```cpp
const char* s = "hi";      // s는 'h'의 주소
cout << s;                 // hi  (cout은 char*를 받으면 주소 대신 '\0'까지의 글자를 출력)
cout << sizeof("hi");      // 3   ('\0' 포함)
cout << strlen(s);         // 2   (<cstring>, '\0' 전까지 센다)

string t = s;              // const char* → string 변환 OK
const char* u = t.c_str(); // string → const char* (C 함수에 넘길 때)
```

> 💡 앞 문서들의 이상한 규칙이 전부 여기서 나온다.
> - `auto s = "hi";`가 `string`이 아니라 `const char*`인 이유 ([02. 자료형 · 연산자](02.cpp_types_operators.md), [12. 템플릿](12.cpp_template.md)의 CTAD)
> - `"ab" + "cd"`가 컴파일 에러인 이유 → **포인터 + 포인터**는 정의되지 않은 연산이라서 ([05. 문자열](05.cpp_string.md))
> - `"abc" + 1`이 `"bc"`가 되는 이유 → 포인터를 한 칸 뒤로 옮긴 것

### const와 포인터

> `const`가 `*`의 **왼쪽**에 있으면 "가리키는 값"이, **오른쪽**에 있으면 "포인터 자체"가 고정된다.

| 선언 | 값(`*p`) 수정 | 다른 곳 가리키기(`p = ...`) |
|------|---------------|------------------------------|
| `const int* p` | ❌ | ✅ |
| `int* const p` | ✅ | ❌ |
| `const int* const p` | ❌ | ❌ |

```cpp
int x = 1, y = 2;
const int* p1 = &x;   // *p1 = 5; ❌   p1 = &y; ✅
int* const p2 = &x;   // *p2 = 5; ✅   p2 = &y; ❌
```

> 💡 **오른쪽에서 왼쪽으로** 읽으면 쉽다. `const int* p` → "p는 / 포인터(`*`) / const int를 가리키는". `int* const p` → "p는 / const인 / 포인터 / int를 가리키는".

### 포인터의 포인터

> 포인터도 변수라서 주소가 있다. 그 주소를 담으면 `int**`가 된다. `main(int argc, char** argv)`나 C 스타일 2차원 동적 배열에서 만난다.

```cpp
int x = 5;
int* p = &x;
int** pp = &p;      // p의 주소
cout << **pp;       // 5  (pp → p → x)
```

## 반복자는 포인터를 흉내 낸 것

> STL 반복자는 **포인터처럼 동작하도록** 만든 객체다. 그래서 문법이 똑같다. `vector`의 반복자는 실제로 내부 배열을 가리키는 포인터를 감싼 것이다.

| 포인터 | 반복자 | 의미 |
|--------|--------|------|
| `*p` | `*it` | 가리키는 값 |
| `p->x` | `it->first` | 가리키는 객체의 멤버 |
| `p++` | `++it` | 다음 원소로 |
| `arr + n` | `v.end()` | 마지막 **다음** |
| `q - p` | `it - v.begin()` | 사이 칸 수 (인덱스) |

```cpp
map<string, int> m = {{"a", 1}};
auto it = m.begin();
cout << it->first << " " << it->second;   // a 1   ( (*it).first 와 같음 )
```

> 💡 [07. 컨테이너 어댑터](07.cpp_container_adapters.md)의 **반복자 무효화**도 포인터로 이해하면 쉽다. `vector`가 커지면서 원소들이 새 메모리로 이사 가면, 옛 주소를 들고 있던 포인터·반복자·참조는 이제 **아무 의미 없는 주소**를 가리킨다.

## 연결 구조 — 연결 리스트 · 트리

> 노드끼리 포인터로 이어 붙인 자료구조. `->`는 "포인터가 가리키는 객체의 멤버"(`(*p).member`의 축약)다.

### 연결 리스트 (만들기 · 순회 · 해제)

```cpp
struct Node {
    int val;
    Node* next;
    Node(int v, Node* n = nullptr) : val(v), next(n) {}
};

// 만들기: 앞에 끼워 넣기 → 3 → 2 → 1
Node* head = nullptr;
for (int i = 1; i <= 3; i++)
    head = new Node(i, head);     // 새 노드가 기존 head를 가리키고, 새 노드가 head가 됨

// 순회
for (Node* cur = head; cur != nullptr; cur = cur->next)
    cout << cur->val << " ";      // 3 2 1

// 해제: 다음 노드 주소를 먼저 챙기고 지운다
while (head != nullptr) {
    Node* nxt = head->next;
    delete head;
    head = nxt;
}
```

> ⚠️ `delete head;` 다음에 `head->next`를 읽으면 이미 반납한 메모리를 읽는 것(댕글링)이다. **지우기 전에 다음 주소를 저장**하는 순서가 중요하다.

### 이진 트리 (재귀 순회)

아래 코드가 만드는 트리:

```text
    2
   / \
  1   3
```

```cpp
struct TreeNode {
    int val;
    TreeNode* left = nullptr;
    TreeNode* right = nullptr;
    TreeNode(int v) : val(v) {}
};

void inorder(TreeNode* node) {       // 중위 순회: 왼쪽 → 자신 → 오른쪽
    if (node == nullptr) return;     // 기저 조건: 빈 자리
    inorder(node->left);
    cout << node->val << " ";
    inorder(node->right);
}

TreeNode* root = new TreeNode(2);
root->left = new TreeNode(1);
root->right = new TreeNode(3);
inorder(root);   // 1 2 3
```

> 💡 코테 트리 문제는 노드 번호와 `vector<int> left(n), right(n)` 같은 **배열 인덱스**로 트리를 표현하는 경우가 더 많다. 포인터 트리는 LeetCode식 문제나 실무 코드에서 주로 만난다.

> 💡 위 트리는 `delete`로 해제하지 않았다. 해제하려면 후위 순회로 자식부터 지워야 한다. 이 번거로움을 없애는 게 [10. 참조 · 메모리](10.cpp_memory.md)의 **스마트 포인터**다.
