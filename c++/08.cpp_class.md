# 🔷 08. 클래스

> 데이터와 그 데이터를 다루는 함수를 하나로 묶는 **클래스**를 다룬다. 접근 지정자, 생성자·소멸자, 멤버 함수, 구조체, 그리고 클래스가 `+`, `==`, `<<` 같은 연산자에 반응하게 만드는 **연산자 오버로딩**까지 다룬다.
>
> 💡 파이썬에서 클래스를 다뤄봤다면 개념은 이어진다. 다만 C++은 접근 제어, 객체의 생성·소멸 시점, 복사 방식을 훨씬 명시적으로 다룬다.

---

## 클래스 기초

### 접근 지정자

> 멤버의 공개 범위를 정한다. 파이썬은 `_` 관례뿐이었지만, C++은 **문법으로 강제**한다.

```cpp
class Dog {
private:               // 외부 접근 불가
    int age;
public:                // 외부 접근 가능
    string name;
    void bark() { cout << "멍멍\n"; }
};
```

| 지정자 | 접근 범위 | 파이썬 대응 |
|--------|-----------|-------------|
| `public` | 어디서나 | (기본) |
| `private` | 클래스 내부만 | `__name` 관례 |
| `protected` | 클래스 + 자식 | `_name` 관례 |

> 💡 `class`는 기본이 `private`, `struct`는 기본이 `public`. 그 차이만 빼면 둘은 동일하다.

### 생성자 / 소멸자

> **생성자** : 객체 생성 시 자동 호출 (파이썬 `__init__`). **소멸자** : 객체 소멸 시 자동 호출.

```cpp
class Dog {
    string name;
public:
    Dog(string n) : name(n) {          // 생성자 (멤버 초기화 리스트)
        cout << name << " 태어남\n";
    }
    ~Dog() {                            // 소멸자 (~클래스명)
        cout << name << " 소멸\n";
    }
};

Dog d("바둑이");   // "바둑이 태어남"
                   // 범위 끝나면 "바둑이 소멸" 자동 호출
```

> 💡 `: name(n)`은 **멤버 초기화 리스트**다. 생성자 본문에서 `name = n` 하는 것보다 효율적이라 권장한다.

### this 포인터

> 멤버 함수 안에서 **자기 자신(객체)을 가리키는 포인터**. 파이썬 `self`에 대응하지만, C++은 자동이라 보통 생략한다.

```cpp
class Dog {
    string name;
public:
    void setName(string name) {
        this->name = name;   // this->name(멤버) = name(매개변수)
    }
};
```

### static / const 멤버

> **static 멤버** : 모든 객체가 공유 (파이썬 클래스 변수). **const 멤버 함수** : 객체 상태를 바꾸지 않음을 보장.

```cpp
class Counter {
public:
    static int count;          // 공유 변수
    int value = 0;

    int getValue() const {     // const 함수: 멤버 수정 안 함
        return value;
    }
};
int Counter::count = 0;        // static 멤버는 외부에서 정의
```

> 💡 C++17부터는 `inline static`으로 선언하면 **클래스 안에서 바로 초기화**할 수 있어 바깥 정의가 필요 없다.
> ```cpp
> class Counter {
> public:
>     inline static int count = 0;   // C++17: 외부 정의 불필요
> };
> ```

## 생성자 더 알아보기

### 기본 생성자와 `= default`

> 인자 없이 객체를 만들 때 불리는 생성자가 **기본 생성자**다. 생성자를 하나도 안 만들면 컴파일러가 자동으로 만들어 주지만, **다른 생성자를 하나라도 만들면 자동 생성이 사라진다.**

```cpp
class Point {
    int x = 0, y = 0;                     // 멤버 기본값 (C++11)
public:
    Point() = default;                    // 기본 생성자를 컴파일러 기본 동작으로 만들어 달라
    Point(int x, int y) : x(x), y(y) {}   // 매개변수 생성자
};

Point a;          // ✅ 기본 생성자 → (0, 0)
Point b(1, 2);    // ✅
Point c{3, 4};    // ✅ 중괄호도 가능
```

> ⚠️ `Point(int x, int y)`만 있고 `Point() = default;`가 없으면 `Point a;`가 **컴파일 에러**다. `vector<Point> v(10);`처럼 기본 생성이 필요한 곳에서도 에러가 난다.

### explicit — 의도치 않은 자동 변환 막기

> 인자 하나짜리 생성자는 **자동 형변환**에 쓰일 수 있다. `explicit`을 붙이면 명시적으로 생성할 때만 허용된다.

```cpp
class Meter {
    double v;
public:
    explicit Meter(double v) : v(v) {}
};

void run(Meter m) {}

run(Meter(3.0));   // ✅
// run(3.0);       // ❌ explicit 덕분에 double → Meter 자동 변환 금지
```

> 💡 인자 하나짜리 생성자에는 기본적으로 `explicit`을 붙이는 습관이 안전하다.

### 멤버 함수를 클래스 밖에서 정의하기

> 클래스 안에는 **선언**만 두고, 본문은 `클래스명::함수명`으로 밖에서 정의할 수 있다. 클래스 선언은 헤더(`.h`), 정의는 소스(`.cpp`)에 두는 실제 프로젝트 구조가 이 방식이다([16. 프로그램 구조](16.cpp_program_structure.md)).

```cpp
class Circle {
    double r;
public:
    Circle(double r);
    double area() const;                      // 선언만
};

Circle::Circle(double r) : r(r) {}            // 생성자 정의
double Circle::area() const {                 // 멤버 함수 정의 (const도 다시 적는다)
    return 3.14159 * r * r;
}
```

### 복사 생성자

> 객체를 **복사**할 때 호출되는 생성자. 대부분은 컴파일러가 자동 생성해줘서 직접 쓸 일이 드물다.

```cpp
struct Box {
    int value;
    Box(const Box& other) {    // 복사 생성자
        value = other.value;
    }
};
```

> 💡 멤버가 `vector`·`string`처럼 복사를 알아서 처리하는 타입이면 복사 생성자를 직접 정의할 일이 거의 없다.

> 💡 **Rule of Zero.** 멤버가 `vector`·`string`·스마트 포인터처럼 스스로 자원을 관리하는 타입뿐이라면, 복사 생성자·복사 대입·이동·소멸자를 **하나도 직접 만들지 마라.** 컴파일러가 만들어주는 것이 정확하다. 직접 `new`로 자원을 쥘 때만 이 다섯 개를 함께 고민해야 한다(Rule of Five). 위의 `Box`처럼 복사 생성자를 하나라도 직접 만들면 기본 생성자가 사라져 `Box b;`가 컴파일되지 않는 것도 주의하자.

## 구조체 (struct)

> 관련 데이터를 하나로 묶는다. `class`와 거의 같지만 **기본 접근이 `public`**이다. 관례적으로 **데이터를 묶는 용도**에는 `struct`, 데이터를 숨기고 기능을 제공하는 타입에는 `class`를 쓴다.

```cpp
struct Point {
    int x, y;
};

Point p = {1, 2};       // 초기화
cout << p.x << p.y;     // 1 2

vector<Point> points;
points.push_back({3, 4});   // 벡터에 담기
```

> 💡 `pair`로도 두 값을 묶지만, 값이 셋 이상이거나 **의미 있는 이름**(`.x`, `.dist`)이 필요하면 `struct`가 훨씬 읽기 좋다.

> 💡 C++17부터 멤버가 전부 `public`인 구조체는 **구조적 바인딩**으로 풀 수 있다.
> ```cpp
> auto [x, y] = p;   // x = 1, y = 2
> ```

## 연산자 오버로딩

> `+`, `==` 같은 연산자를 클래스에 맞게 정의. (파이썬의 `__add__` 등 매직 메서드에 대응)

```cpp
struct Point {
    int x, y;
    Point operator+(const Point& o) const {   // + 정의
        return {x + o.x, y + o.y};
    }
    bool operator==(const Point& o) const {    // == 정의
        return x == o.x && y == o.y;
    }
};

Point a{1, 2}, b{3, 4};
Point c = a + b;   // (4, 6)
```

> 💡 실제로 가장 자주 쓰는 오버로딩은 출력용 `operator<<`와 정렬 기준이 되는 `operator<`다(아래 참고). 구조체를 컨테이너 키로 쓸 때 필요한 것은 컨테이너마다 다르다.
>
> | 컨테이너 | 키 타입에 필요한 것 |
> |----------|---------------------|
> | `set` / `map` | `operator<` |
> | `unordered_set` / `unordered_map` | `operator==` **+ 해시 함수** (직접 정의해야 해서 번거롭다) |
>
> 그래서 구조체 키는 보통 `operator<`만 정의하고 `set`/`map`을 쓴다.

### 출력 연산자 `<<` 오버로딩

> `cout << p`처럼 객체를 바로 출력하려면 `operator<<`를 **클래스 밖의 함수**로 정의한다. 왼쪽 피연산자가 내 클래스가 아니라 `ostream`(`cout`)이기 때문이다.

```cpp
struct Point {
    int x, y;
};

ostream& operator<<(ostream& os, const Point& p) {
    return os << "(" << p.x << ", " << p.y << ")";   // os를 반환해야 << 를 이어 쓸 수 있다
}

Point p{1, 2};
cout << p << "\n";   // (1, 2)
```

> 💡 `private` 멤버를 출력해야 하면 클래스 안에 `friend ostream& operator<<(ostream&, const Point&);`로 선언해 접근을 허락한다.

### operator< 로 정렬 기준 정의

> 구조체에 `operator<`를 정의하면 `sort`가 그 기준으로 정렬한다. **정렬 기준을 타입에 내장**하는 방식.

```cpp
struct Student {
    string name;
    int score;

    bool operator<(const Student& other) const {
        return score > other.score;   // 점수 내림차순
    }
};

vector<Student> v = {{"A", 80}, {"B", 95}, {"C", 90}};
sort(v.begin(), v.end());   // operator< 기준 → 95, 90, 80 순
```

> ⚠️ `operator<`는 **"같을 때 false"**를 반환해야 한다(strict weak ordering). 다중 기준이면 앞 기준이 같을 때 다음 기준으로 넘겨라.
> ```cpp
> bool operator<(const Student& o) const {
>     if (score != o.score) return score > o.score;  // 1순위: 점수 내림차순
>     return name < o.name;                           // 2순위: 이름 오름차순
> }
> ```

### priority_queue에서의 구조체

> `priority_queue`에 구조체를 담으면 `operator<`를 기준으로 정렬된다. **`operator<`에서 "우선순위 낮음"을 참으로** 두면 그 반대가 top에 온다.

```cpp
struct Job {
    int priority;
    bool operator<(const Job& o) const {
        return priority < o.priority;   // priority 큰 게 top (최대 힙)
    }
};
priority_queue<Job> pq;   // priority가 가장 큰 Job이 top
```

> 💡 정렬 기준이 즉석에서 필요하면 `struct` 대신 **람다**([13. STL 알고리즘](13.cpp_algorithm.md))를 `sort`에 넘기는 게 더 간편하다. 타입에 고정된 기준이면 `operator<`, 그때그때 다르면 람다 — 이렇게 구분하면 된다.
