# 🔷 04. 함수

> 코드를 이름 붙인 단위로 묶는 **함수**의 정의와 호출, 인자를 넘기는 방식(값·참조·const 참조), 기본 인자와 오버로딩, 재귀, 이름 없는 함수인 **람다**, 그리고 여러 형태의 **반환값**을 다룬다.

---

## 함수 기초

### 함수 구조

> 특정 작업을 묶어 이름 붙인 코드. C++은 **반환 타입을 명시**해야 한다.

```cpp
int add(int a, int b) {   // 반환타입 함수이름(매개변수)
    return a + b;
}

void greet(string name) { // void = 반환값 없음
    cout << "Hi, " << name << "\n";
}
```

| 구성 | 의미 |
|------|------|
| 반환 타입 | 돌려줄 값의 타입 (`int`, `double`, `bool`...) |
| `void` | 반환값 없음 |
| 매개변수 | 받을 입력 (타입 명시 필수) |
| `return` | 결과 반환 + 함수 즉시 종료 |

### 선언과 정의 분리 (프로토타입)

> C++은 함수를 **호출하기 전에 알고 있어야** 한다. 정의가 `main` 아래에 있으면 위에 **선언(프로토타입)**만 먼저 적는다.

```cpp
int add(int a, int b);   // 선언 — 본문 없이 세미콜론

int main() {
    cout << add(3, 5);   // 정의가 아래 있어도 OK
}

int add(int a, int b) {  // 정의
    return a + b;
}
```

> 💡 파일 하나짜리 프로그램에선 함수를 `main` **위에** 정의해서 선언(프로토타입)을 생략하는 경우가 많다.

> 💡 선언·정의 구분은 여러 파일로 나눈 프로그램에서 "헤더에 선언, `.cpp`에 정의"라는 규칙이 된다([16. 프로그램 구조](16.cpp_program_structure.md) 참고).

## 매개변수 전달 방식

### 값 / 참조 / const 참조

> C++은 인자를 넘기는 방식에 따라 **원본을 바꿀 수 있느냐**와 **복사 비용**이 갈린다. 특히 **큰 컨테이너를 복사 없이 넘기는 것**이 성능에 직결된다.

**① 값 전달 (복사)** — 원본 안 바뀜. 큰 데이터엔 비효율.
```cpp
void f(int x) { x = 100; }   // 복사본만 변경
int a = 5;
f(a);
cout << a;   // 5  (원본 그대로)
```

**② 참조 전달 (`&`)** — 원본을 직접 가리킴. 바뀜.
```cpp
void f(int& x) { x = 100; }  // 원본 변경
int a = 5;
f(a);
cout << a;   // 100  (바뀜!)
```

**③ const 참조 (`const &`)** — 복사 없이 넘기되 수정은 막음. **큰 데이터 읽기 전용 전달의 표준.**
```cpp
long long sum(const vector<int>& v) {   // 벡터를 복사 없이 참조
    long long s = 0;
    for (int x : v) s += x;
    return s;
}
```

| 방식 | 문법 | 원본 변경 | 복사 비용 | 용도 |
|------|------|-----------|-----------|------|
| 값 | `int x` | ❌ | 있음 | 작은 값 단순 입력 |
| 참조 | `vector<int>& v` | ✅ | 없음 | 원본 수정 |
| const 참조 | `const vector<int>& v` | ❌ | 없음 | **큰 데이터 읽기 전용** |

> ⚠️ **`vector`·`string`을 값으로 넘기면 통째로 복사된다.** 원소가 10만 개면 호출마다 10만 번 복사 → 프로그램이 느려지는 숨은 원인이다. 수정할 거면 `&`, 읽기만 하면 `const &`로 넘겨라.

> 💡 **2차원 벡터를 여러 함수가 공유**한다면 전역 변수로 두거나 `&`로 넘긴다. 값 복사는 절대 피한다.

### 기본 인자

> 인자를 생략하면 기본값 사용. 단 **뒤쪽 매개변수부터** 기본값을 줘야 한다.

```cpp
int power(int base, int exp = 2) {   // exp 기본값 2
    int r = 1;
    for (int i = 0; i < exp; i++) r *= base;
    return r;
}
power(3);      // 9  (3^2)
power(3, 3);   // 27 (3^3)
```

> ⚠️ 기본값 있는 매개변수는 **반드시 뒤쪽**에. `int f(int a = 1, int b)` ❌

### 함수 오버로딩

> **같은 이름** 함수를 매개변수 구성만 다르게 여러 개 정의. 컴파일러가 인자 타입·개수를 보고 알맞은 버전을 고른다.

```cpp
int    add(int a, int b)       { return a + b; }
double add(double a, double b)  { return a + b; }

add(1, 2);       // int 버전 → 3
add(1.5, 2.5);   // double 버전 → 4.0
```

## 재귀 함수

### 기본 구조

> 자기 자신을 호출하는 함수. **종료 조건(기저 조건)**이 반드시 있어야 한다. DFS·백트래킹·분할정복의 토대다.

```cpp
int factorial(int n) {
    if (n <= 1) return 1;          // 기저 조건 (종료점)
    return n * factorial(n - 1);   // 자기 자신 호출
}
factorial(5);   // 120
```

| 요소 | 설명 |
|------|------|
| 기저 조건 | 재귀를 멈추는 조건 (필수) |
| 재귀 호출 | 더 작은 문제로 자기 자신 호출 |

> ⚠️ 파이썬은 재귀 한도(`RecursionError`)로 막아줬지만, C++은 한도가 없어도 **스택 메모리를 초과(stack overflow)하면 그냥 죽는다**(segfault). 재귀 깊이가 수십만이면 반복문이나 명시적 스택으로 바꾸는 걸 고려하라.

## 람다 표현식

> 이름 없는 함수를 그 자리에서 정의한다. `[캡처](매개변수) { 본문 }` 형태. `sort`의 비교 기준처럼 **함수를 인자로 넘길 때** 특히 많이 쓴다.

```cpp
auto add = [](int a, int b) { return a + b; };
cout << add(3, 5);   // 8

// sort 비교 기준으로 (가장 흔한 용도)
vector<int> v = {3, 1, 2};
sort(v.begin(), v.end(), [](int a, int b) {
    return a > b;    // 내림차순
});
```

바깥 변수를 **캡처**해 람다 안에서 쓸 수 있다(파이썬 람다보다 강력).

```cpp
int base = 10;
auto addBase = [base](int x) { return x + base; };  // base를 값으로 캡처
cout << addBase(5);  // 15
```

| 캡처 | 의미 |
|------|------|
| `[]` | 캡처 없음 |
| `[base]` | base를 값(복사)으로 캡처 |
| `[&base]` | base를 참조로 캡처 (원본 수정 가능) |
| `[=]` / `[&]` | 바깥 변수 전부 값 / 전부 참조 |

> 💡 C++14부터 **제네릭 람다**가 된다. 매개변수에 `auto`를 쓸 수 있다.
> ```cpp
> auto cmp = [](auto a, auto b) { return a > b; };
> ```

### 재귀 람다

> 람다는 이름이 없어서 **자기 자신을 바로 호출할 수 없다.** `main` 안의 지역 변수를 `[&]`로 캡처한 채 DFS를 짜고 싶을 때 아래 두 방법 중 하나를 쓴다.

```cpp
#include <functional>
vector<vector<int>> adj = {{1, 2}, {3}, {}, {}};   // 인접 리스트
vector<bool> vis(4, false);

// 방법 1: std::function에 담기 (읽기 쉬움)
function<void(int)> dfs = [&](int u) {
    vis[u] = true;
    for (int v : adj[u])
        if (!vis[v]) dfs(v);
};
dfs(0);   // 0 → 1 → 3 → 2

// 방법 2: 자기 자신을 인자로 넘기기 (C++14 제네릭 람다, 더 빠름)
auto dfs2 = [&](auto& self, int u) -> void {
    for (int v : adj[u]) self(self, v);
};
dfs2(dfs2, 0);
```

> 💡 `function`은 호출마다 약간의 오버헤드가 있다. 재귀가 수백만 번이면 방법 2나 일반 함수 + 전역 변수가 낫다. 방법 2는 반환 타입(`-> void`)을 꼭 적어야 컴파일된다.

## 반환값 다루기

> 함수가 결과를 돌려주는 여러 방법과, 반환할 때 주의할 점.

### 참조 반환 주의

> 함수가 **지역 변수의 참조**를 반환하면, 함수가 끝나며 그 변수가 사라져 **댕글링 참조**가 된다.

```cpp
int& bad() {
    int x = 5;
    return x;      // ❌ x는 함수 종료 시 소멸 → 위험
}
```

> 💡 값을 돌려줄 땐 그냥 값으로 반환하라(`int f()`, `vector<int> f()`). C++은 반환 시 복사를 생략(RVO)하므로 대부분 비용 걱정이 없다. **C++17부터는** `return vector<int>(n);`처럼 임시 객체를 바로 반환하면 복사 생략이 **표준으로 보장**된다. 이름 있는 지역 변수를 반환할 때도 컴파일러가 거의 항상 생략하고, 못 해도 복사 대신 **이동**([07. 참조와 메모리 관리](07.cpp_memory.md) 참고)한다.

### 반환 타입 추론 (auto)

> C++14부터 함수 반환 타입도 `auto`로 추론할 수 있다.

```cpp
auto multiply(int a, int b) {   // 반환 타입 int로 추론
    return a * b;
}
```

### 여러 값 반환 (구조적 바인딩, C++17)

> `pair`나 `tuple`로 묶어 반환하고, 받는 쪽에서 **구조적 바인딩**으로 바로 푼다. (파이썬 `q, r = divmod(17, 5)`에 대응)

```cpp
pair<int, int> divmod(int a, int b) {
    return {a / b, a % b};
}

auto [q, r] = divmod(17, 5);   // q = 3, r = 2
```

### 값이 없을 수 있는 반환 (optional, C++17)

> "찾으면 값, 못 찾으면 없음"을 `-1` 같은 특수값 대신 `std::optional`로 표현한다. (`#include <optional>`)

```cpp
#include <optional>
optional<int> findIndex(const vector<int>& v, int x) {
    for (int i = 0; i < (int)v.size(); i++)
        if (v[i] == x) return i;
    return nullopt;                         // 값 없음
}

vector<int> v = {1, 3, 5};
if (auto idx = findIndex(v, 3)) {           // 값이 있으면 참
    cout << *idx << "\n";                   // 1  (*로 값 꺼내기)
}
cout << findIndex(v, 9).value_or(-1);       // -1 (없으면 기본값)
```

> 💡 "못 찾으면 `-1`" 같은 특수값은 `-1`도 정상 값일 수 있는 함수에선 헷갈린다. `optional`은 "값 없음"을 타입으로 분명히 표현한다.
