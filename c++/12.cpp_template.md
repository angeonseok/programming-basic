# 🔷 C++ 기초 문법 — 템플릿 · 제네릭

> **템플릿** : 타입을 매개변수처럼 받아 **여러 타입에 동작하는 코드를 한 번만** 작성하는 기능. (파이썬은 동적 타입이라 필요 없던 개념 — C++ 고유)
>
> 💡 **코테 관점:** 직접 템플릿을 작성할 일은 드물다. 하지만 **네가 쓰는 STL이 전부 템플릿**(`vector<T>`, `sort` 등)이라, 원리를 알면 STL을 더 자유롭게 다룰 수 있다. 가끔 "타입만 다른 유틸 함수"를 하나로 묶을 때 유용하다.

---

## 함수 템플릿

> 타입만 다르고 로직이 같은 함수를 **하나로** 작성한다.

```cpp
template <typename T>      // T = 타입 매개변수
T getMax(T a, T b) {
    return (a > b) ? a : b;
}

getMax(3, 7);        // int 버전 → 7
getMax(1.5, 2.5);    // double 버전 → 2.5
getMax('a', 'z');    // char 버전 → 'z'
```

> 💡 `typename` 대신 `class`를 써도 같다 (`template <class T>`). 컴파일러가 호출 시 타입을 보고 **버전을 자동 생성**한다.

> ⚠️ 두 인자의 타입이 다르면 `T`를 하나로 정할 수 없어 **컴파일 에러**다. `std::max(a, b)`에 `int`와 `long long`을 섞으면 에러가 나는 이유도 같다([08. 알고리즘](08.cpp_algorithm.md) 참고).
> ```cpp
> // getMax(3, 2.5);        // ❌ T가 int인지 double인지 모호
> getMax<double>(3, 2.5);   // ✅ T를 직접 지정 → 3은 double로 변환
> ```

> 💡 코테에선 이런 일반화보다 **함수 오버로딩**([04. 함수](04.cpp_functions.md))이나 그냥 필요한 타입으로 여러 개 쓰는 게 더 흔하다. 템플릿은 "타입이 정말 여러 개일 때"의 선택지다.

## 클래스 템플릿

> 클래스 전체를 타입에 대해 일반화. (STL의 `vector<T>`, `map<K,V>`가 전부 이 방식)

```cpp
template <typename T>
class Box {
    T value;
public:
    Box(T v) : value(v) {}
    T get() { return value; }
};

Box<int> a(5);        // T = int
Box<string> b("hi");  // T = string
cout << a.get();      // 5
```

### 클래스 템플릿 인자 추론 (CTAD, C++17)

> C++17부터는 **클래스 템플릿도 생성자 인자로 타입을 추론**한다(Class Template Argument Deduction). 함수 템플릿(`getMax(3, 7)`)처럼 `<>`를 생략할 수 있다.

```cpp
Box c(5);                 // Box<int>
Box d(3.5);               // Box<double>
pair p{1, 2.5};           // pair<int, double>
vector v = {1, 2, 3};     // vector<int>
```

> ⚠️ 문자열 리터럴은 `string`이 아니라 **`const char*`**로 추론된다. `Box s("hi");`는 `Box<const char*>`다. `string`이 필요하면 `Box<string>`처럼 타입을 명시하라.

> 💡 코테 코드에선 `vector<int>`처럼 타입을 적는 편이 읽기 쉽고 실수가 적다. CTAD는 타입 이름이 길 때 쓰면 된다.

### 여러 타입 매개변수

> 타입 매개변수를 둘 이상 받을 수 있다.

```cpp
template <typename K, typename V>
struct Pair {
    K key;
    V value;
};

Pair<string, int> p{"age", 25};

// 기본 타입 인자도 가능
template <typename T = int>   // 기본 타입 int
class Stack { /* ... */ };

Stack<> s;        // T = int (기본)
Stack<double> d;  // T = double
```

## 참고

### STL과 템플릿의 관계

> 앞에서 쓴 STL이 전부 템플릿으로 만들어졌다. 그래서 `<>` 안에 타입을 넣어 쓰는 것이다.

| 사용 | 실제 정체 |
|------|-----------|
| `vector<int>` | 클래스 템플릿 `vector<T>`에 `T = int` |
| `map<string,int>` | `map<K,V>`에 `K = string, V = int` |
| `priority_queue<int, vector<int>, greater<int>>` | 세 템플릿 인자를 지정 |
| `sort(...)` | 함수 템플릿 (반복자 타입 추론) |

> 💡 즉 STL을 쓰는 순간 이미 템플릿을 쓰고 있던 것이다. `priority_queue`의 `greater<int>`가 왜 `<>`를 갖는지도 이 맥락에서 이해된다 — 그것도 템플릿(비교자 타입)이다.

### 제네릭 람다 (C++14)

> C++14부터 람다 매개변수에 `auto`를 쓸 수 있다. 사실상 즉석 함수 템플릿이다.

```cpp
auto add = [](auto a, auto b) { return a + b; };
add(1, 2);       // 3
add(1.5, 2.5);   // 4.0
```

> 💡 코테에서 템플릿을 직접 쓸 일이 있다면 대개 이 제네릭 람다 정도다. 정렬 비교 등에 타입을 안 가리게 하고 싶을 때 편하다.

### if constexpr (C++17)

> 템플릿 안에서 **컴파일 시점에** 분기한다. 조건이 거짓인 쪽 코드는 그 타입에 대해 아예 만들어지지 않는다. 일반 `if`였다면 `to_string("hi")` 같은 코드 때문에 컴파일 에러가 난다.

```cpp
#include <type_traits>
template <typename T>
string describe(T x) {
    if constexpr (is_integral_v<T>) {
        return "정수 " + to_string(x);
    } else {
        return "정수 아님";
    }
}

describe(5);      // "정수 5"
describe("hi");   // "정수 아님" (to_string 쪽은 만들어지지 않음)
```

### fold expression (C++17)

> 가변 인자 템플릿(`typename... Args`)의 인자들을 연산자 하나로 **접어서** 계산한다.

```cpp
template <typename... Args>
auto sum(Args... args) {
    return (args + ...);   // a1 + (a2 + (a3 + ...))
}

sum(1, 2, 3);      // 6
sum(1.5, 2, 3);    // 6.5
```

> 💡 `if constexpr`와 fold expression은 코테에서 직접 쓸 일이 드물다. 라이브러리나 실무 코드를 읽을 때 만나는 문법이다.
