# 🔷 C++ 기초 문법 — 객체 지향 (OOP) · 구조체

> 파이썬에서 클래스를 다뤄봤다면 개념은 이어진다. C++은 **생성자/소멸자, 접근 지정자, virtual**을 명시적으로 다룬다.
>
> 💡 **코테 관점:** OOP를 깊게 쓰는 문제는 드물다. 하지만 **`struct`로 데이터를 묶고, `operator<`나 비교 함수로 정렬·우선순위 큐 기준을 정하는 것**은 매우 자주 쓴다. 그 부분을 특히 챙겨두자.

## 구조체와 정렬 (코테 핵심)

### struct — 여러 값 묶기

> 관련 데이터를 하나로 묶는다. `class`와 거의 같지만 **기본 접근이 `public`**이라 코테에선 `struct`가 편하다.

```cpp
struct Point {
    int x, y;
};

Point p = {1, 2};       // 초기화
cout << p.x << p.y;     // 1 2

vector<Point> points;
points.push_back({3, 4});   // 벡터에 담기
```

> 💡 `pair`로도 두 값을 묶지만, 값이 셋 이상이거나 **의미 있는 이름**(`.x`, `.dist`)이 필요하면 `struct`가 훨씬 읽기 좋다.

> 💡 C++17부터 멤버가 전부 `public`인 구조체는 **구조적 바인딩**으로 풀 수 있다.
> ```cpp
> auto [x, y] = p;   // x = 1, y = 2
> ```

### operator< 로 정렬 기준 정의

> 구조체에 `operator<`를 정의하면 `sort`가 그 기준으로 정렬한다. **정렬 기준을 타입에 내장**하는 방식.

```cpp
struct Student {
    string name;
    int score;

    bool operator<(const Student& other) const {
        return score > other.score;   // 점수 내림차순
    }
};

vector<Student> v = {{"A", 80}, {"B", 95}, {"C", 90}};
sort(v.begin(), v.end());   // operator< 기준 → 95, 90, 80 순
```

> ⚠️ `operator<`는 **"같을 때 false"**를 반환해야 한다(strict weak ordering). 다중 기준이면 앞 기준이 같을 때 다음 기준으로 넘겨라.
> ```cpp
> bool operator<(const Student& o) const {
>     if (score != o.score) return score > o.score;  // 1순위: 점수 내림차순
>     return name < o.name;                           // 2순위: 이름 오름차순
> }
> ```

### priority_queue에서의 구조체

> `priority_queue`에 구조체를 담으면 `operator<`를 기준으로 정렬된다. **`operator<`에서 "우선순위 낮음"을 참으로** 두면 그 반대가 top에 온다.

```cpp
struct Job {
    int priority;
    bool operator<(const Job& o) const {
        return priority < o.priority;   // priority 큰 게 top (최대 힙)
    }
};
priority_queue<Job> pq;   // priority가 가장 큰 Job이 top
```

> 💡 정렬 기준이 즉석에서 필요하면 `struct` 대신 **람다**(`06.cpp_stl_algorithm`)를 `sort`에 넘기는 게 더 간편하다. 타입에 고정된 기준이면 `operator<`, 그때그때 다르면 람다 — 이렇게 구분하면 된다.

## 클래스 기초

### 접근 지정자

> 멤버의 공개 범위를 정한다. 파이썬은 `_` 관례뿐이었지만, C++은 **문법으로 강제**한다.

```cpp
class Dog {
private:               // 외부 접근 불가
    int age;
public:                // 외부 접근 가능
    string name;
    void bark() { cout << "멍멍\n"; }
};
```

| 지정자 | 접근 범위 | 파이썬 대응 |
|--------|-----------|-------------|
| `public` | 어디서나 | (기본) |
| `private` | 클래스 내부만 | `__name` 관례 |
| `protected` | 클래스 + 자식 | `_name` 관례 |

> 💡 `class`는 기본이 `private`, `struct`는 기본이 `public`. 그 차이만 빼면 둘은 동일하다.

### 생성자 / 소멸자

> **생성자** : 객체 생성 시 자동 호출 (파이썬 `__init__`). **소멸자** : 객체 소멸 시 자동 호출.

```cpp
class Dog {
    string name;
public:
    Dog(string n) : name(n) {          // 생성자 (멤버 초기화 리스트)
        cout << name << " 태어남\n";
    }
    ~Dog() {                            // 소멸자 (~클래스명)
        cout << name << " 소멸\n";
    }
};

Dog d("바둑이");   // "바둑이 태어남"
                   // 범위 끝나면 "바둑이 소멸" 자동 호출
```

> 💡 `: name(n)`은 **멤버 초기화 리스트**다. 생성자 본문에서 `name = n` 하는 것보다 효율적이라 권장한다.

### this 포인터

> 멤버 함수 안에서 **자기 자신(객체)을 가리키는 포인터**. 파이썬 `self`에 대응하지만, C++은 자동이라 보통 생략한다.

```cpp
class Dog {
    string name;
public:
    void setName(string name) {
        this->name = name;   // this->name(멤버) = name(매개변수)
    }
};
```

### static / const 멤버

> **static 멤버** : 모든 객체가 공유 (파이썬 클래스 변수). **const 멤버 함수** : 객체 상태를 바꾸지 않음을 보장.

```cpp
class Counter {
public:
    static int count;          // 공유 변수
    int value = 0;

    int getValue() const {     // const 함수: 멤버 수정 안 함
        return value;
    }
};
int Counter::count = 0;        // static 멤버는 외부에서 정의
```

> 💡 C++17부터는 `inline static`으로 선언하면 **클래스 안에서 바로 초기화**할 수 있어 바깥 정의가 필요 없다.
> ```cpp
> class Counter {
> public:
>     inline static int count = 0;   // C++17: 외부 정의 불필요
> };
> ```

## 상속과 다형성

### 상속 기본

> 부모 클래스의 멤버를 물려받는다. `: public 부모`로 표기. (파이썬 `class Dog(Animal)`)

```cpp
class Animal {
public:
    void eat() { cout << "먹는다\n"; }
};

class Dog : public Animal {    // Animal 상속
public:
    void bark() { cout << "멍멍\n"; }
};

Dog d;
d.eat();   // 부모에게서 물려받음
d.bark();  // 자식 고유
```

> 💡 대부분 `public` 상속을 쓴다. `protected`/`private` 상속은 코테에선 거의 볼 일이 없다.

### 부모 생성자 호출

> 자식 생성자에서 부모 생성자를 호출하려면 **초기화 리스트**에 적는다. (파이썬 `super().__init__()`)

```cpp
class Dog : public Animal {
    string name;
public:
    Dog(string n) : Animal(), name(n) {   // 부모 생성자 명시 호출
        // 부모에 인자 필요하면 : Animal(n), name(n)
    }
};
```

### virtual / 오버라이딩

> 부모 메서드를 `virtual`로 두면, 자식이 재정의했을 때 **실제 객체 타입의 메서드가 호출**된다(다형성). 파이썬은 기본이 이 동작이다.

```cpp
class Animal {
public:
    virtual void speak() { cout << "...\n"; }   // virtual
    virtual ~Animal() {}                        // 가상 소멸자 (다형성 쓰면 필수)
};

class Dog : public Animal {
public:
    void speak() override { cout << "멍멍\n"; }  // override
};

Animal* a = new Dog();
a->speak();   // "멍멍"  (포인터는 Animal이지만 실제는 Dog → 다형성)
delete a;
```

> ⚠️ `virtual`을 안 붙이면 **포인터 타입 기준**으로 호출돼 `"..."`이 나온다. 다형성을 원하면 `virtual` 필수다.

> 💡 실제 코드에선 `new`/`delete` 대신 스마트 포인터를 쓴다(`07.cpp_pointer_memory` 참고). 다형성은 그대로 동작하고 `delete`를 잊을 일이 없다.
> ```cpp
> unique_ptr<Animal> b = make_unique<Dog>();
> b->speak();   // "멍멍"  (b가 사라질 때 자동 delete)
> ```

> ⚠️ 상속·다형성을 쓸 클래스의 소멸자는 **반드시 `virtual`**로. 아니면 부모 포인터로 `delete`할 때 자식 소멸자가 안 불려 누수가 난다.

### 추상 클래스 / 순수 가상 함수

> `= 0`으로 선언한 **순수 가상 함수**가 있으면 그 클래스는 **추상 클래스**(객체 생성 불가, 자식이 반드시 구현). (파이썬 ABC에 대응)

```cpp
class Shape {
public:
    virtual double area() = 0;   // 순수 가상 함수
    virtual ~Shape() = default;  // 가상 소멸자 (= default: 기본 동작 그대로)
};

class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() override { return 3.14 * r * r; }  // 반드시 구현
};

// Shape s;    ❌ 추상 클래스라 생성 불가
Circle c(5);   // ✅
```

## 참고

### 연산자 오버로딩

> `+`, `==` 같은 연산자를 클래스에 맞게 정의. (파이썬의 `__add__` 등 매직 메서드에 대응)

```cpp
struct Point {
    int x, y;
    Point operator+(const Point& o) const {   // + 정의
        return {x + o.x, y + o.y};
    }
    bool operator==(const Point& o) const {    // == 정의
        return x == o.x && y == o.y;
    }
};

Point a{1, 2}, b{3, 4};
Point c = a + b;   // (4, 6)
```

> 💡 코테에서 자주 쓰는 오버로딩은 정렬용 `operator<`(위 참고)다. 구조체를 컨테이너 키로 쓸 때 필요한 것은 컨테이너마다 다르다.
>
> | 컨테이너 | 키 타입에 필요한 것 |
> |----------|---------------------|
> | `set` / `map` | `operator<` |
> | `unordered_set` / `unordered_map` | `operator==` **+ 해시 함수** (직접 정의해야 해서 번거롭다) |
>
> 그래서 구조체 키는 보통 `operator<`만 정의하고 `set`/`map`을 쓴다.

### 복사 생성자

> 객체를 **복사**할 때 호출되는 생성자. 대부분은 컴파일러가 자동 생성해줘서 직접 쓸 일이 드물다.

```cpp
struct Box {
    int value;
    Box(const Box& other) {    // 복사 생성자
        value = other.value;
    }
};
```

> 💡 코테에선 `vector`·`string`이 복사를 알아서 처리하므로 복사 생성자를 직접 정의할 일이 거의 없다.

> 💡 **Rule of Zero.** 멤버가 `vector`·`string`·스마트 포인터처럼 스스로 자원을 관리하는 타입뿐이라면, 복사 생성자·복사 대입·이동·소멸자를 **하나도 직접 만들지 마라.** 컴파일러가 만들어주는 것이 정확하다. 직접 `new`로 자원을 쥘 때만 이 다섯 개를 함께 고민해야 한다(Rule of Five). 위의 `Box`처럼 복사 생성자를 하나라도 직접 만들면 기본 생성자가 사라져 `Box b;`가 컴파일되지 않는 것도 주의하자.
